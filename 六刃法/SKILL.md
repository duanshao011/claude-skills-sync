## 定位

对单条知识做深度拆解，不依赖其他笔记，纯粹用多视角思考框架把一条知识吃透。核心目的不是信息汇总，而是确认自己是否真的理解、能不能输出最小行动。

## 什么时候用

- 存了一条知识但感觉还没吃透
- 想确认自己是不是真的理解了
- 一条知识一直没用起来，需要重新激活

## 流程

### Step 1：输入

接收待拆解的知识内容：
- 方式 A：用户直接粘贴笔记内容或要点
- 方式 B：用户说"榨干 [[笔记名]]"，读取对应笔记内容
- 方式 C：用户提供外部链接（URL） → 调用 `/web-access` skill 抓取全文后拆解，不要问用户（本地文件路径直接 Read）

### Step 2：多刀切割

对知识内容做 6 刀拆解，每刀产出明确结论：

**刀一：溯源刃**
追问到底层假设。剥掉所有中间推论，找到这条知识最底层的、不证自明的前提。

```
这条知识最底层的假设是什么？
如果这个假设不成立，这条知识还成立吗？
它依赖的"不证自明"的前提有哪些？
```

**刀二：悖论刃**
找内在矛盾和反直觉面。看它在什么条件下对、什么条件下反转。

```
这条知识在什么情况下是对的，什么情况下反过来也成立？
它和被广泛接受的常识冲突在哪？
它内部有没有自相矛盾的地方？
```

**刀三：反转刃**
把核心前提翻转 180°，看还能不能成立。

```
如果反过来才是对的，会怎样？
这条知识的反面，有没有同样成立甚至更有解释力的例子？
```

**刀四：笨拙刃**
剥掉术语和包装，用人话说清楚本质。

```
用一句话说给初中生听，它到底在说什么？
去掉所有修饰词，剩下的本质是什么？
```

**刀五：尺度刃**
拉大或缩小时间/空间尺度，看它怎么变。

```
放到更长的时间维度（10年）看，还成立吗？
缩小到极端微观的场景，还适用吗？
放大到行业/社会层面，意味着什么？
```

**刀六：杠杆刃**
找这条知识里最值钱的 20%。

```
如果只记住一点，是哪一点？
哪个部分是"知道就行"，哪个部分是"知道了但做不到就白搭"？
```

### Step 3：输出

基于拆解结果，产出结构化结论：

```
## 榨干结果：{知识标题}

**一句话本质**
→ 去掉所有包装，这条知识的核心是什么

**拆解收获**
- 底层假设：xxx
- 反直觉/矛盾：xxx
- 反转视角：xxx
- 杠杆支点：xxx
- 尺度变化：xxx

**理解升级**
→ 拆解前和拆解后，我对这条知识的理解有什么不同

**最小行动**
→ 这条知识在我身上产生改变的最小动作
```

## 关键设计原则

1. **单条拆解** — 不依赖其他笔记，纯粹靠思考框架榨干内容
2. **行动导向** — 最终产出必须有"最小行动"，否则拆解没有落地
3. **说人话** — 笨拙刃强制要求用人话表达，避免术语掩盖理解缺口
4. **不超 6 刀** — 刀数固定，避免过度分析
5. **理解升级是核心** — 拆解前后必须有明确的认知变化，否则等于没拆
