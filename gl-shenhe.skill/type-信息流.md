# 信息流类审核指南

## 一、类型定义

**什么算信息流：**
- 短片拍摄脚本，总时长建议40-60秒
- 投放在信息流广告位（抖音/小红书信息流）
- 用户是"刷到"而非主动搜索，前3秒决定是否继续看
- 核心追求：场景代入 + 情绪沉浸 + 自然种草
- 全片语气像"游泳爱好者分享日常"，不像"产品介绍"
- **信息流是种草不是拔草，不出现价格/优惠信息**

**与其他两种类型的核心区别：**

| 维度 | 深度评测 | 使用分享 | 信息流 |
|------|---------|---------|--------|
| 时长 | 60秒+ | 不限 | 40-60秒 |
| 用户状态 | 主动点进来看 | 刷到感兴趣停留 | 被动刷到，随时划走 |
| 审核重心 | 结构完整+种草深度 | 口语真实感+情感共鸣 | **文案表达+种草深度** |
| 卖点策略 | 3-5个系统拆解 | 1-3个深入体验 | 2-3个重点打透，其他带过 |
| 结构要求 | 完整模块化（8维度） | 有基本逻辑线 | 7段式（4维度精简审核） |
| 风格 | 自然即可 | 像真人聊天 | 情绪价值优先，个人体验角度 |
| 价格信息 | 可以有算账逻辑 | 可以有价值锚定 | **禁止出现价格/优惠** |

---

## 二、审核维度（4维度 + 红线）

> 信息流审核使用独立的4维度评分体系，不套用深度评测的8维度框架。

### 维度1：文案表达（权重35%）

**审核核心问题：这段文案读起来像一个游泳爱好者在分享日常，还是品牌方在念稿？卖点是否被"翻译"成了体验？**

| 分数 | 特征 |
|------|------|
| 9-10 | 有个人语言特征，情绪感染力强，读完想去游泳。所有功能都用"我在用的那个瞬间"来表达 |
| 7-8 | 像真人说话，有情绪价值，大部分卖点已转化为体验描述，但个别句子仍偏功能介绍 |
| 5-6 | 部分自然部分广告腔，语言不统一。卖点和体验混杂，一会儿像分享一会儿像念参数 |
| 3-4 | 功能描述+感叹词组合，像产品页改写。卖点基本没有翻译，用"它有XX功能"而非"我用起来感觉XX" |
| 1-2 | 说明书/品牌稿直接读。"搭载XX技术""支持XX功能"贯穿全文 |

**审核要点：**
- 是否以个人体验和情绪价值为主线？
- **卖点是否翻译成了体验？**（核心判断：每句话是在说"它有什么功能"还是"我用起来怎么样"。前者是说明书，后者是种草）
- 是否避免了说明书式表达（"搭载XX技术""支持XX功能""配套小程序"）？
- 字幕/口播是否口语化，有呼吸节奏？
- 是否有"我"的视角和感受，而非第三人称介绍？
- 模板词检查：宝藏/闭眼入/超顶等高频模板词出现2个以上扣分
- 发现说明书式表达时，参照下方"卖点→体验翻译工具箱"给出改写建议

### 维度2：种草深度（权重30%）

**审核核心问题：是否有1-2个功能被"打透"了，而非每个功能都浅尝辄止？**

> **信息流是减法**——砍到只剩1-2个核心体验，其他一句带过。行业共识："都是卖点=没有卖点"。40-60秒最多打透2个功能，其他功能要么收尾顺嘴一句，要么直接砍掉。

| 分数 | 特征 |
|------|------|
| 9-10 | 只聚焦1-2个核心功能，有场景+体验+情绪三层打透，其他功能最多一句带过 |
| 7-8 | 重点功能有足够篇幅和体验细节，主次分明，非核心功能没有独立展开 |
| 5-6 | 有重点但不够深，或非核心功能展开过多，挤占了核心段时长 |
| 3-4 | 每个功能都提了但都浅，像功能清单。典型特征：防雾、近视、训练计划、数据分析每个都独立成段 |
| 1-2 | 纯功能罗列，无场景无体验，像评测的删减版 |

**审核要点：**
- 是否有1-2个功能获得重点篇幅（占全片1/3以上）？
- 重点功能是否有场景描写和体验感受，而非只说"有这个功能"？
- 非重点功能是否控制在"一句话"以内？（防雾、近视、续航等加分项不应独立成段）
- 是否避免了评测式硬核讲解（拆参数、逐项打分）？
- **禁止出现价格/优惠信息**（信息流是种草不是拔草）
- 功能平铺的典型信号：每个功能5-8秒均匀分配时间，没有一个功能获得压倒性篇幅

### 维度3：脚本结构（权重20%）

**审核核心问题：脚本是否有清晰的节奏线，而非功能堆砌？**

| 分数 | 特征 |
|------|------|
| 9-10 | 7段式结构完整，时长分配合理，节奏有起伏 |
| 7-8 | 结构基本完整，个别段偏长或偏短 |
| 5-6 | 有结构但节奏不好，某段过重或缺失 |
| 3-4 | 结构混乱，像评测删减版 |
| 1-2 | 无结构，功能堆砌 |

**审核要点：**
- 是否符合7段式结构？（底层逻辑：Hook→核心卖点打透→过渡→收尾，加分项功能放收尾而非前置）
- 核心卖点段时长是否占全片1/3以上？
- 各段之间是否有自然过渡，不突兀跳转？
- 总时长是否在40-60秒范围？
- **脚本方向是否合理？** 开头3秒的切入方式是否匹配产品和受众？常见方向参考：
  - 痛点直述型：直接展示游泳中遇到的问题（"以前游泳全靠瞎感觉"）
  - 效果表达型：口播+画面直接展示使用效果
  - 人群锚定型：开头点名目标人群（"一个人练游泳的姐妹"）
  - 悬念揭秘型：引发好奇再揭晓（"糟糕忘带手表了！没事..."）
  - 塑造情绪型：用场景/动作传递变化感
- **结构是否像"评测删减版"？** 如果近视、防雾、密封性等加分项各自独立成段放在核心前面，说明结构思路是"评测缩短"而非"信息流原生"，需重新设计

### 维度4：基础错误检查（权重15%）

和深度评测标准完全一致，对照 `product-knowledge.md` 逐项验证：
- 产品名称、型号是否正确
- 技术参数是否准确（续航、防水等级、存储容量等）
- 是否有禁忌词（骨传导、智商税、方案等）
- 功能边界是否正确
- 话题标签是否齐全
- **信息流专属：不出现价格/优惠信息**

---

## 三、评分机制

| 分数 | 等级 | 含义 |
|------|------|------|
| 85+ | 优秀 | 基本不用改 |
| 70-84 | 良好 | 小优化 |
| 60-69 | 合格 | 有明显问题需修改 |
| <60 | 不合格 | 需要重写 |

加权计算：文案表达35% + 种草深度30% + 脚本结构20% + 基础错误15%

红线命中单独标注，不影响分数但必须修改。

---

## 四、通用红线（命中即标记）

以下规则适用于所有信息流脚本，不分产品：

| 序号 | 规则 | 影响 |
|------|------|------|
| 1 | 前3秒禁止纯产品特写开头，必须有人/场景/动作 | 降低广告感 |
| 2 | 核心卖点段时长必须占全片三分之一以上 | 内容质量 |
| 3 | 封面和正片严禁纯身材/泳衣擦边镜头 | 合规 |
| 4 | 字幕不要和画面内容重叠，底部留出平台交互栏空间 | 画面规范 |
| 5 | 全片语气像"游泳爱好者分享日常"，不要像"产品介绍" | 风格调性 |
| 6 | 功能种草画面需有字幕或口播，不能只有游泳画面无信息 | 信息传达 |

> 各产品还有专属红线，见对应模板部分。

---

逐条列出命中的通用红线 + 产品专属红线。全部通过则一行带过。

**一句话总结。**

# SollaWave AI音乐泳镜 信息流模板 v2.0

> 基于：SollaWave AI音乐泳镜信息流脚本模板 v2.0
> 核心情绪线：**游泳从无聊变有趣，从坚持不下去到不想上岸**
> 核心卖点场景：水下听歌的沉浸感和爽感

## SW专属红线

| 序号 | 规则 | 影响 |
|------|------|------|
| SW-1 | 水下听歌部分是全片情绪核心，时长必须占全片三分之一以上 | 内容质量 |
| SW-2 | 数据播报不要让达人停下来对着镜头讲，要在游的过程中用字幕自然叠加 | 自然度 |
| SW-3 | 进行数据播报时，背景音乐调小，避免听感混乱 | 制作细节 |

## SW 7段式结构模板

### 第1段：Hook · 场景代入（3-5秒）

**要求：**
- 游泳中/游泳后的一个瞬间，传递"变化感"
- 可以是出水甩头、靠在泳池边喘气、摘泳镜的动作
- **禁止产品特写开头**

**字幕参考方向：**
- 自从泳镜能放歌，我游泳从800变成了1500
- 一个人游泳终于不无聊了
- 被泳池里的音乐治愈到不想上岸

**审核要点：** 是否在3秒内建立场景代入？是否避开了产品特写开头？

### 第2段：痛点+产品出场（5-8秒）

**要求：**
- 简单一句带出以前游泳的问题
- 展示佩戴泳镜准备下水，佩戴过程自然露出产品外观
- 不需要360度展示

**口播参考方向：**
- 以前一个人游泳真的很难坚持，又无聊又没节奏
- 后来换了这个能听歌的泳镜，直接不一样了

**审核要点：** 痛点是否真实？产品出场是否自然而非硬塞？

### 第3段：水下听歌 · 情绪主体（15-20秒）★全片重点★

**要求：**
- 水下游泳画面 + 音乐可视化（后期加歌词浮层/播放器贴片/歌单切换）
- 展示游泳过程中听歌的爽感和沉浸感
- 入耳式贴合画面在这里自然带到
- **此段时长必须占全片三分之一以上**

**字幕参考方向：**
- 发明音乐泳镜的真是天才
- 入水瞬间音乐响起，整个泳池都是我的
- 入耳式在水下音质居然没差别
- 谁能忍住不唱啊

**审核要点：** 时长是否达标（占全片1/3以上）？是否有音乐氛围感？是否让观众"感受到"而非"被告知"？

### 第4段：实时数据播报 · 自然穿插（5-8秒）

**要求：**
- 游泳过程中，在耳朵旁边加字幕模拟语音播报内容
- 画面是正在游的状态
- **不要停下来专门展示**

**字幕参考方向：**
- 耳旁浮层：您已游泳800米 / 32趟 / 用时18分钟
- 底部字幕：全程语音播报，不用抬头看表，节奏完全不断

**审核要点：** 数据播报是否在游泳过程中自然叠加？是否避免了"停下来讲解"？背景音乐是否调小？

### 第5段：出水 · 节奏转折（3-5秒）

**要求：**
- 出水动作，摘泳镜或靠池边
- 从水下沉浸感切换到日常感

**字幕参考方向：**
- 可不加字幕，或轻松一句：又不小心多游了500米

### 第6段：数据分析 · 成就感（5-8秒）

**要求：**
- 手机App数据页面展示，今天的游泳成绩
- 画面是手持手机+泳池背景，不是纯录屏

**字幕参考方向：**
- 今天1500米达成
- 有了数据记录，每次都想比上次多游一点

### 第7段：收尾 · 轻种草（3-5秒）

**要求：**
- 重新佩戴泳镜或收拾装备离开的画面
- 耗材可换信息一句话口语化带过

**字幕参考方向：**
- 而且胶圈镜片都能换，不像以前泳镜用半年就扔
- 反正我现在游泳离不开它了

## SW 封面与文案

### 封面要求
- 人在泳池中佩戴泳镜的运动场景（非产品摆拍）

- 泳池里唱歌被人盯着看

**不合格标题：** 直接提品牌名、像广告语、无场景感、含"神器/科技/黑科技"等营销词

### 必带话题
`#光粒SollaWaveAI音乐泳镜` `#游泳耳机` `#音乐泳镜` `#智能泳镜` `#泳镜` `#近视泳镜` `#游泳装备` `#游泳` `#HoloSport泳镜` `#游泳装备`

# Holoswim 3系列 信息流模板 v1.0

> 适用产品：Holoswim 3 / Holoswim 3 Pro（参数差异见产品知识库）
> 基于：Holoswim 2 Pro 信息流脚本模板，升级为 Holoswim 3 参数
> 核心情绪线：**游泳从凭感觉到有数据，从随意游到有节奏地练**
> 核心卖点场景：AR数据浮现在眼前，边游边看，不打断节奏

## H3 专属红线

| 序号 | 规则 | 影响 |
|------|------|------|
| H3-1 | AR数显第一视角是全片核心，时长必须占全片三分之一以上 | 内容质量 |
| H3-2 | AR数显画面必须清晰完整，数据可读，每次展示2秒以上 | 功能展示质量 |
| H3-3 | Vlog形式视频需在前10秒内出现泳镜镜头或第一视角数显画面 | 产品露出时效 |
| H3-4 | 非评测类型不展示开箱，直接植入泳镜 | 风格调性 |
| H3-5 | 不提GPS功能（Holoswim 3不支持，3 Pro本月不推） | 产品禁忌 |
| H3-6 | 不说"自带心率监测"（需搭配灵狐心率计配件） | 产品禁忌 |

## H3 7段式结构模板

### 第1段：Hook · 场景代入（3-5秒）

**要求：**
- 日常泳池场景，自然露出智能泳镜
- 传递"游泳有了节奏感/掌控感"
- 不要纯产品特写开头，应有人在场景中

**字幕参考方向：**
- 以前游泳全靠瞎感觉，现在终于有人帮我盯配速啦
- 糟糕忘带手表了！没事我有智能泳镜
- 一个人游泳也能认真练，原来就差这个功能

**审核要点：** 是否快速建立"科技感+日常感"？是否避开了纯产品摆拍？

### 第2段：痛点+产品出场（5-8秒）

**要求：**
- 一句话带出以前游泳的问题（凭感觉游、不知道配速、总要停下来看表等）
- 佩戴泳镜准备下水，自然露出产品外观
- 可以同时展示App设置训练目标的画面

**口播参考方向：**
- 平时一个人游泳，最大的问题就是容易越游越随意。配速靠猜，游完只知道累
- 用了光粒智能泳镜之后，变化还挺明显

**审核要点：** 痛点是否是游泳爱好者的真实困扰？产品出场是否自然？

### 第3段：AR数显 · 核心主体（15-20秒）★全片重点★

**要求：**
- 第一视角拍摄AR数据显示（配速、距离、时间、圈数等）
- AR画面必须清晰完整，数据可读
- 竖屏显示画面饱满，强光下也看得清（600nit亮度）
- 多角度展示：刚下水时 / 游泳过程中 / 游完时
- **此段时长必须占全片三分之一以上**

**字幕参考方向：**
- 数据直接显在眼前，不用抬手，不用停，边游边看
- 以前是凭感觉游，现在是边游边调配速，节奏稳多了
- 游泳也很有"安全感"

**审核要点：** 时长是否达标（占全片1/3以上）？第一视角画面是否清晰？是否传递出"不打断节奏"的核心价值？是否避免了硬核参数讲解？

### 第4段：训练计划 · 功能种草（5-8秒）

**要求：**
- App设置训练计划 → 下水跟着练
- 画面可以是"App画面+泳池画中画"或"泳镜中训练计划提示的第一视角"
- 不要纯App录屏，要有人+场景

**字幕参考方向：**
- 提前设好目标跟着游就行，真的很像把私教戴在脸上
- 对我这种平时不知道怎么练的人太好用了

**审核要点：** 训练计划功能是否用体验感受表达，而非功能说明？

### 第5段：游泳画面 · 节奏转折（3-5秒）

**要求：**
- 水下动态画面（转身、翻滚、换气等）
- 传递佩戴稳固、密封好、流线型轻量
- 视觉上从"看数据"切换到"享受游泳"

**字幕参考方向：**
- 佩戴很舒服，密封性特别好，翻滚跳水都没漏过水
- 可不加字幕，纯画面节奏过渡

**审核要点：** 是否有动态画面丰富度？是否避免了视频单一枯燥？

### 第6段：游后数据 · 成就感（5-8秒）

**要求：**
- 手机App数据页面展示今天的游泳成绩
- 画面是手持手机+泳池背景，或画中画，不是纯录屏
- 用视频背景虚化等方式避免纯贴图

**字幕参考方向：**
- 今日游泳计划达成，App上一眼就清楚了
- 看看今天的数据，越游越有动力

**审核要点：** 数据展示是否有场景感（人+背景）？是否避免了纯截图/纯录屏？

### 第7段：收尾 · 轻种草（3-5秒）

**要求：**
- 自然收尾，可以带一句加分项功能（防雾/近视/续航等）
- 不要硬推，像顺嘴提一句

**口播参考方向：**
- 防雾也做得很好，游了一小时还是清晰的
- 近视也能用，直接做进镜片里，不用贴片，左右眼度数还能分开定
- 想提升游泳质量的，这个可以试试

**审核要点：** 收尾是否轻松自然？加分项是否只一句带过不展开？

# 通用参考

## 与产品知识库的关系

两款产品的信息流脚本都要对照 `product-knowledge.md` 审核，重点查：
- 禁忌词/夸大表述（口语化不等于可以乱说）
- 核心卖点是否在产品能力范围内
- 话题标签是否齐全
- **不出现价格/优惠信息**

## 信息流正文改写规则（案例提炼）

> 来源：2026-06-22 SW信息流笔记正文审核，原文功能清单式→优化为体验沉浸式。以下规则适用于所有信息流笔记正文审核和改写。

### 规则1：标题-正文主线一致
标题暗示的内容方向必须和正文核心段一致。标题讲"游泳无聊→音乐改变了"，正文核心就要讲听歌体验，不能讲"五合一功能介绍"。审核时用**替换测试**：把正文核心段删掉，标题是否失去了承接？如果是，说明匹配；如果标题独立成立，说明脱节。

### 规则2：品牌全称延后
品牌全称不出现在正文前50%。前文用品类描述自然代替（"能听歌的泳镜""一副能放歌的泳镜"），品牌全称放后半段或末尾。

### 规则3：功能场景化
用"我在用的那个瞬间"展示功能，不用"它有什么功能"来介绍。

| ❌ 功能描述式 | ✅ 场景化 |
|-------------|----------|
| 支持水下听歌 | 下水歌直接响起来 |
| 实时语音播报距离配速 | 耳边突然报了一句"已游800米" |
| 五合一整合泳镜耳机耳塞 | 出门只带这一副，泳镜耳机耳塞全齐了 |

### 规则4：变化感+具体数字
用前后对比+数字替代空洞形容词。数据实证：标题正文含具体数字（米/斤/分钟）的笔记，高停留组是低停留组的4倍。

| ❌ 空洞 | ✅ 有变化感 |
|--------|-----------|
| 轻松拿捏 | 以前游500米就想上岸，现在1000米都停不下来 |
| 太快乐了 | 游着游着一首歌没听完，不知不觉就过了1000米 |
| 被惊艳到 | 不用靠岸停表看数据，节奏完全不断 |

### 规则5：第一人称沉浸
全文保持"我"视角。不跳到"你""大家""姐妹们"的介绍视角。"告诉你游了多远"→"耳边报了一句已游800米"，"陪你游到底"→"安安静静游完回家"。

### 规则6：功能整合后置轻带
多功能整合的卖点放在体验段之后，一句话带过，不前置不展开。"出门只带这一副"而非"五合一神器全部搞定"。

### 规则7：收尾用日常画面
用一个具体的日常动作收尾，不用广告式总结语。"反正我现在去泳池，就带它一个，安安静静游完回家"而非"专属智能搭子，陪你游到底✨"。

## 常见问题速查

| 问题 | 影响维度 | 处理建议 |
|------|---------|----------|
| 产品特写开头 | 通用红线#1 | 必须改为人/场景/动作开头 |
| 核心卖点段太短 | 通用红线#2 | 时长必须占全片1/3以上 |
| 全片像产品说明书 | 文案表达 + 通用红线#5 | 回到"日常分享"风格 |
| 每个功能都泛泛而谈 | 种草深度 | 砍到2-3个重点打透，其他一句带过 |
| 像评测的删减版 | 脚本结构 | 信息流不是评测缩短版，需重新设计 |
| 出现价格/优惠 | 基础错误 | 删除，信息流只种草不拔草 |
| 硬核拆参数 | 种草深度 | 改为体验感受描述，不做参数讲解 |
| 笔记文案硬广 | 文案表达 | 参考模板改为真人分享口吻 |
| 话题标签不全 | 基础错误 | 对照对应产品必带话题补齐 |
| 2Pro参数张冠李戴到3 | 基础错误（H3专属） | 对照H3注意事项表逐项验证 |
