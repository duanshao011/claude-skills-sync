# 信息流类审核指南

> **基于：** SollaWave AI音乐泳镜信息流脚本模板 v2.0

## 一、类型定义

**什么算信息流：**
- 短片拍摄脚本，总时长建议40-60秒
- 投放在信息流广告位（抖音/小红书信息流）
- 用户是"刷到"而非主动搜索，前3秒决定是否继续看
- 核心追求：场景代入 + 情绪沉浸 + 自然种草
- 全片语气像"游泳爱好者分享日常"，不像"产品介绍"
- **信息流是种草不是拔草，不出现价格/优惠信息**

**与其他两种类型的核心区别：**

| 维度 | 深度评测 | 使用分享 | 信息流 |
|------|---------|---------|--------|
| 时长 | 60秒+ | 不限 | 40-60秒 |
| 用户状态 | 主动点进来看 | 刷到感兴趣停留 | 被动刷到，随时划走 |
| 审核重心 | 结构完整+种草深度 | 口语真实感+情感共鸣 | **文案表达+种草深度** |
| 卖点策略 | 3-5个系统拆解 | 1-3个深入体验 | 2-3个重点打透，其他带过 |
| 结构要求 | 完整模块化（8维度） | 有基本逻辑线 | 7段式（4维度精简审核） |
| 风格 | 自然即可 | 像真人聊天 | 情绪价值优先，个人体验角度 |
| 价格信息 | 可以有算账逻辑 | 可以有价值锚定 | **禁止出现价格/优惠** |

---

## 二、审核维度（4维度 + 红线）

> 信息流审核使用独立的4维度评分体系，不套用深度评测的8维度框架。

### 维度1：文案表达（权重35%）

**审核核心问题：这段文案读起来像一个游泳爱好者在分享日常，还是品牌方在念稿？**

| 分数 | 特征 |
|------|------|
| 9-10 | 有个人语言特征，情绪感染力强，读完想去游泳 |
| 7-8 | 像真人说话，有情绪价值，但辨识度一般 |
| 5-6 | 部分自然部分广告腔，语言不统一 |
| 3-4 | 功能描述+感叹词组合，像产品页改写 |
| 1-2 | 说明书/品牌稿直接读 |

**审核要点：**
- 是否以个人体验和情绪价值为主线（"变化感""沉浸感""爽感"）？
- 是否避免了说明书式表达（"搭载XX技术""支持XX功能"）？
- 字幕/口播是否口语化，有呼吸节奏？
- 是否有"我"的视角和感受，而非第三人称介绍？
- 模板词检查同深度评测：宝藏/闭眼入/超顶等高频模板词出现2个以上扣分

### 维度2：种草深度（权重30%）

**审核核心问题：是否有2-3个功能被"打透"了，而非每个功能都浅尝辄止？**

| 分数 | 特征 |
|------|------|
| 9-10 | 重点功能有场景+体验+情绪三层，其他功能一句带过不抢戏 |
| 7-8 | 重点功能有足够篇幅和体验细节，主次分明 |
| 5-6 | 有重点但不够深，或者功能分配不均匀 |
| 3-4 | 每个功能都提了但都浅，像功能清单 |
| 1-2 | 纯功能罗列，无场景无体验 |

**审核要点：**
- 是否有2-3个功能获得重点篇幅（如水下听歌、数据播报、防雾等）？
- 重点功能是否有场景描写和体验感受，而非只说"有这个功能"？
- 非重点功能是否简洁带过，不喧宾夺主？
- 是否避免了评测式硬核讲解（拆参数、逐项打分）？
- **禁止出现价格/优惠信息**（信息流是种草不是拔草）
- 模块化可换等成本类信息可以一句带过，不做重点

### 维度3：脚本结构（权重20%）

**审核核心问题：脚本是否有清晰的节奏线，而非功能堆砌？**

| 分数 | 特征 |
|------|------|
| 9-10 | 7段式结构完整，时长分配合理，节奏有起伏 |
| 7-8 | 结构基本完整，个别段偏长或偏短 |
| 5-6 | 有结构但节奏不好，某段过重或缺失 |
| 3-4 | 结构混乱，像评测删减版 |
| 1-2 | 无结构，功能堆砌 |

**审核要点：**
- 是否符合7段式结构（Hook→痛点→情绪主体→数据播报→出水→数据分析→收尾）？
- 情绪主体段（水下听歌）时长是否占全片1/3以上？
- 各段之间是否有自然过渡，不突兀跳转？
- 总时长是否在40-60秒范围？

### 维度4：基础错误检查（权重15%）

和深度评测标准完全一致，对照 `product-knowledge.md` 逐项验证：
- 产品名称、型号是否正确
- 技术参数是否准确（续航、防水等级、存储容量等）
- 是否有禁忌词（骨传导、智商税、方案等）
- 功能边界是否正确（SW无GPS、不支持公开水域等）
- 话题标签是否齐全
- **信息流专属：不出现价格/优惠信息**

## 三、评分机制

| 分数 | 等级 | 含义 |
|------|------|------|
| 85+ | 优秀 | 基本不用改 |
| 70-84 | 良好 | 小优化 |
| 60-69 | 合格 | 有明显问题需修改 |
| <60 | 不合格 | 需要重写 |

加权计算：文案表达35% + 种草深度30% + 脚本结构20% + 基础错误15%

红线命中单独标注，不影响分数但必须修改。

---

## 四、7条硬性红线（命中即标记）

审核时逐条检查，命中任一条在报告中标记：

| 序号 | 规则 | 影响 |
|------|------|------|
| 1 | 前3秒禁止产品特写开头，必须是人/场景/动作 | 降低广告感 |
| 2 | 水下听歌部分是全片情绪核心，时长必须占全片三分之一以上 | 内容质量 |
| 3 | 数据播报不要让达人停下来对着镜头讲，要在游的过程中用字幕自然叠加 | 自然度 |
| 4 | 封面和正片严禁纯身材/泳衣擦边镜头 | 合规 |
| 5 | 字幕不要和画面内容重叠，底部留出平台交互栏空间 | 画面规范 |
| 6 | 全片语气像"游泳爱好者分享日常"，不要像"产品介绍" | 风格调性 |
| 7 | 进行数据播报时，背景音乐调小，避免听感混乱 | 制作细节 |

## 六、7段式结构模板（审核对照标准）

审核信息流脚本时，逐段对照以下结构检查：

### 第1段：Hook · 场景代入（3-5秒）

**要求：**
- 游泳中/游泳后的一个瞬间，传递"变化感"
- 可以是出水甩头、靠在泳池边喘气、摘泳镜的动作
- **禁止产品特写开头**

**字幕参考方向：**
- 自从泳镜能放歌，我游泳从800变成了1500
- 一个人游泳终于不无聊了
- 被泳池里的音乐治愈到不想上岸

**审核要点：** 是否在3秒内建立场景代入？是否避开了产品特写开头？

### 第2段：痛点+产品出场（5-8秒）

**要求：**
- 简单一句带出以前游泳的问题
- 展示佩戴泳镜准备下水，佩戴过程自然露出产品外观
- 不需要360度展示

**口播参考方向：**
- 以前一个人游泳真的很难坚持，又无聊又没节奏
- 后来换了这个能听歌的泳镜，直接不一样了

**审核要点：** 痛点是否真实？产品出场是否自然而非硬塞？

### 第3段：水下听歌 · 情绪主体（15-20秒）★全片重点★

**要求：**
- 水下游泳画面 + 音乐可视化（后期加歌词浮层/播放器贴片/歌单切换）
- 展示游泳过程中听歌的爽感和沉浸感
- 入耳式贴合画面在这里自然带到
- **此段时长必须占全片三分之一以上**

**字幕参考方向：**
- 发明音乐泳镜的真是天才
- 入水瞬间音乐响起，整个泳池都是我的
- 入耳式在水下音质居然没差别
- 谁能忍住不唱啊

**审核要点：** 时长是否达标（占全片1/3以上）？是否有音乐氛围感？是否让观众"感受到"而非"被告知"？

### 第4段：实时数据播报 · 自然穿插（5-8秒）

**要求：**
- 游泳过程中，在耳朵旁边加字幕模拟语音播报内容
- 画面是正在游的状态
- **不要停下来专门展示**

**字幕参考方向：**
- 耳旁浮层：您已游泳800米 / 32趟 / 用时18分钟
- 底部字幕：全程语音播报，不用抬头看表，节奏完全不断

**审核要点：** 数据播报是否在游泳过程中自然叠加？是否避免了"停下来讲解"的广告感？背景音乐是否调小避免听感混乱？

### 第5段：出水 · 节奏转折（3-5秒）

**要求：**
- 出水动作，摘泳镜或靠池边
- 从水下沉浸感切换到日常感

**字幕参考方向：**
- 可不加字幕，或轻松一句：又不小心多游了500米

**审核要点：** 是否有节奏转换？过渡是否自然？

### 第6段：数据分析 · 成就感（5-8秒）

**要求：**
- 手机App数据页面展示，今天的游泳成绩
- 画面是手持手机+泳池背景，不是纯录屏

**字幕参考方向：**
- 今天1500米达成
- 有了数据记录，每次都想比上次多游一点

**审核要点：** 是否是真实场景展示（手持手机+背景），而非纯录屏？

### 第7段：收尾 · 轻种草（3-5秒）

**要求：**
- 重新佩戴泳镜或收拾装备离开的画面
- 耗材可换信息一句话口语化带过

**字幕参考方向：**
- 而且胶圈镜片都能换，不像以前泳镜用半年就扔
- 反正我现在游泳离不开它了

**审核要点：** 收尾是否轻松自然？是否避免了硬推产品？

## 七、封面与文案审核标准

### 封面要求
- 人在泳池中佩戴泳镜的运动场景（非产品摆拍）
- 可叠加歌单截图/歌词浮层作为视觉钩子
- **严禁纯身材/泳衣擦边镜头**

### 标题审核
围绕"游泳+听歌"的反差感或变化感，参考方向：
- 游了1500米才摘泳镜，发现人都走了
- 以前游500米就想上岸，现在要被管理员赶
- 泳池里唱歌被人盯着看

**不合格标题：** 直接提品牌名、像广告语、无场景感

### 必带话题
`#光粒SollaWaveAI音乐泳镜` `#游泳耳机` `#音乐泳镜` `#智能泳镜` `#泳镜` `#近视泳镜` `#游泳装备` `#游泳` `#HoloSport泳镜` `#游泳装备`

## 八、笔记正文参考模板

审核配套笔记文案时，参考以下风格和结构：

> 一个人游泳的姐妹听我说
>
> 以前每次游到500米就开始数还剩几趟，越数越不想游
> 后来换了光粒SollaWave AI音乐泳镜，下水直接放歌
> 游着游着一首歌没听完，不知不觉就过了1000米
>
> 而且全程语音播报距离和配速，不用停下来看表
> 节奏稳，效率高，游完心情还特别好
>
> 现在每次去泳池就是我的音乐时间
> 反正我是回不去没有BGM的游泳了

**审核要点：** 文案是否像真人分享？是否有场景+变化+种草的逻辑线？是否避免了硬广口吻？

## 十、与产品知识库的关系

信息流虽然时间不算短（40-60秒），但因为追求自然分享感，禁忌词的影响更大（口语化表达容易踩线）。审核时重点查：
- 禁忌词/夸大表述（口语化不等于可以乱说）
- 核心卖点是否在产品能力范围内
- 话题标签是否齐全
- **不出现价格/优惠信息**

## 十一、常见问题速查

| 问题 | 影响维度 | 处理建议 |
|------|---------|----------|
| 产品特写开头 | 红线#1 | 必须改为人/场景/动作开头 |
| 水下听歌段太短 | 红线#2 + 脚本结构 | 时长必须占全片1/3以上 |
| 数据播报时停下讲解 | 红线#3 | 改为游泳中字幕叠加 |
| 全片像产品说明书 | 文案表达 + 红线#6 | 需要重新设计，回到"日常分享"风格 |
| 每个功能都泛泛而谈 | 种草深度 | 砍到2-3个重点打透，其他一句带过 |
| 像评测的删减版 | 脚本结构 | 信息流不是评测缩短版，需重新设计 |
| 出现价格/优惠 | 基础错误 | 删除，信息流只种草不拔草 |
| 硬核拆参数 | 种草深度 | 改为体验感受描述，不做参数讲解 |
| 笔记文案硬广 | 文案表达 | 参考模板改为真人分享口吻 |
| 话题标签不全 | 基础错误 | 对照必带话题补齐 |
