# Search · 脚本·深度评测 审核指南

## 一、类型定义

**什么算 Search · 深度评测：**
- 用户主动搜索"XX测评""XX怎么样""XX值不值得买"后看到的视频脚本
- 口播视频、模块化结构、多维度拆解、横测对比、避雷/选购攻略
- 含镜头/画面描述、分镜、时长分配
- 核心任务：帮用户做决策——系统拆解产品，给出明确判断
- 总时长 2-5 分钟

**子类识别：**

| 子类 | 信号 | 典型搜索词 |
|------|------|----------|
| **单品深度测评** | 围绕一款产品做多维度实测拆解 | "XX泳镜测评""XX值不值得买" |
| **横测对比** | 2款以上产品/方案横向对比 | "XX vs XX""哪款XX好" |
| **避雷/选购攻略** | 踩雷款介绍+推荐款引导 | "千万别买错XX""XX选购攻略" |

> ⚠️ 文案美化技巧（场景强化/贩卖焦虑等）**不适用于 Search 类型**。深度评测的核心是信息准确、结构完整、判断明确，不是情绪渲染。

## 二、审核维度（7维度）

| 维度 | 占比 | 说明 |
|------|------|------|
| 脚本结构 | 15% | 模块覆盖完整吗？维度间有递进逻辑吗？ |
| 种草顺序 | 15% | 卖点有主次层级吗？最先讲的是用户最易感知的吗？ |
| 种草深度 | 15% | 每个卖点有场景+实测+数据吗？不是功能罗列 |
| 口语化 | 15% | 自然表达，不是说明书腔 |
| 诚实度 | 15% | 每模块带槽点？有"不适合谁"？（横测不适用，替换为下方产品对比公平性） |
| 基础错误 | 15% | 参数密集，出错概率高 |
| 节奏与承接 | 10% | 模块间过渡自然吗？ |
| 产品对比公平性 | 15% | 仅横测。对比维度统一吗？被排除的竞品有交代吗？ |

---

### 维度1：脚本结构

**审核核心问题：结构完整吗？模块逻辑清晰吗？**

| 分数 | 特征 |
|------|------|
| 9-10 | 模块完整覆盖，各维度有递进逻辑（由基础到体验），时长分配合理 |
| 7-8 | 结构基本完整，个别模块偏弱或顺序可优化 |
| 5-6 | 缺失1-2个重要模块，或维度平铺无递进 |
| 3-4 | 结构混乱，功能堆砌，缺少评测逻辑 |
| 1-2 | 无结构，纯产品介绍 |

**单品深度测评推荐结构：**
1. 钩子（0-5s）— 结论前置或痛点切入
2. 产品概览（5-30s）— 外观/参数/价格等基础信息
3. 核心功能实测（30s-2min）— 3-4个维度逐个拆，每维度：场景→体验→数据
4. 真实槽点（20-40s）— 客观列出不足和使用注意 ★必须
5. 适用人群+总结（10-20s）— 适合谁/不适合谁

**横测推荐结构：**
1. 开场hook（5%）— 选择困难切入
2. 产品一览（10-15%）— 逐一介绍参评产品
3. **分维度对比（50-60%）** — 3-5个维度逐一对比，用统一标准
4. 结果汇总（10-15%）— 表格/图表展示
5. 分场景推荐（5-10%）— "训练为主选A，休闲为主选B"

**审核要点：**
- 开头是否快速点题？（不要求Feeds级Hook，但要点明测什么）
- 核心功能实测是否按维度组织，而非散乱罗列？
- 维度顺序是否合理（最易感知的优先）？
- 横测：每个维度是否逐一评价所有产品？排除的产品是否有交代？

**"伪横测"识别：**
开头摆多款产品，但后续没有按维度逐一对比，实质是单品测评 → 脚本结构降级。

| 特征 | 伪横测 ❌ | 真横测 ✅ |
|------|----------|----------|
| 开头 | 摆产品+标价，没说对比维度 | 明确说"从哪几个维度来聊" |
| 对比方式 | 围绕主推品拆卖点，竞品插入式吐槽 | 每维度逐一评价所有产品 |
| 产品公平性 | 部分产品几乎未参评 | 排除有明确交代 |
| 结尾 | 只推荐一个 | 按需求分层推荐 |

---

### 维度2：种草顺序

**审核核心问题：卖点有主次层级吗？递进逻辑对吗？**

| 分数 | 特征 |
|------|------|
| 9-10 | 一级卖点在最前、篇幅最重，二三级依次递进，认知逻辑清晰 |
| 7-8 | 主次分明但个别次要卖点位置偏前 |
| 5-6 | 有排序意识但执行不到位，前后重要度差不多 |
| 3-4 | 卖点平铺，无主次之分 |
| 1-2 | 顺序混乱，核心卖点被淹没 |

**审核要点：**
- 一级卖点是否有足够篇幅？（最先出现、篇幅最重）
- 二级卖点是否服务于一级卖点？
- 三级卖点和细节是否放在后面？
- 卖点顺序是否符合用户认知逻辑（先吸引再说服）？

---

### 维度3：种草深度

**审核核心问题：每个卖点有场景+实测+数据支撑吗？**

| 分数 | 特征 |
|------|------|
| 9-10 | 每个核心卖点有场景描述+实测体验+数据佐证三层打透 |
| 7-8 | 大部分卖点有实测支撑，个别维度的数据或场景偏弱 |
| 5-6 | 有实测但停留在"用了感觉不错"，缺少具体数据和对比 |
| 3-4 | 功能罗列为主，偶尔插入体验感受 |
| 1-2 | 纯功能清单，无实测无体验 |

**审核要点：**
- 核心卖点是否有具体场景+实测+数据？
- 是否避免了空泛形容词堆砌（"很好用""很舒服"）？
- 数据是否有可验证性（"游了1500米，手表记录1498米"而非"数据很准"）？
- 评测类专项：必须有"不适合谁"或真实槽点，全正面=直接降级

---

### 维度4：口语化

**审核核心问题：表达是否自然？像不像一个懂行的人在跟你讲？**

| 分数 | 特征 |
|------|------|
| 9-10 | 像懂行的朋友在给你做功课，专业但不端着 |
| 7-8 | 整体自然，个别句子偏书面或偏广告腔 |
| 5-6 | 部分段落像说明书，部分像真人说话，风格不统一 |
| 3-4 | 明显的品牌稿/说明书腔 |
| 1-2 | 纯技术文档风格 |

**审核要点：**
- 模板词检查：宝藏/闭眼入/超顶等，2个以上扣分
- 不要求情绪驱动（和Feeds不同），但要求自然表达
- 专业术语有没有转化成用户听得懂的话？

---

### 维度5：诚实度（横测不适用）

**审核核心问题：是在帮用户做决策，还是在推销？**

| 分数 | 特征 |
|------|------|
| 9-10 | 每个模块带真实槽点或使用注意，有明确的"不适合谁"，判断明确不模糊 |
| 7-8 | 有槽点但集中在某一段，未做到每模块带一个 |
| 5-6 | 有槽点但轻描淡写，或"不适合谁"模糊 |
| 3-4 | 全篇正面，无任何槽点或限制说明 → **红线命中** |
| 1-2 | 纯广告稿 |

**审核要点：**
- 每个评测模块的结论段是否带有使用注意/局限？
- "不适合谁"是否明确具体？
- 横测：每款产品是否都有公正的优缺点评价？

---

### 维度6：产品对比公平性（仅横测）

**横测子类独立维度，单品测评不适用。**

| 分数 | 特征 |
|------|------|
| 9-10 | 对比维度统一、标准一致，每款产品公正评价，排除品有明确交代 |
| 7-8 | 大体公平，个别维度对某款产品略偏 |
| 5-6 | 部分维度对比不充分，或排除品交代模糊 |
| 3-4 | 明显偏袒主推品，竞品被不公平对待 |
| 1-2 | 拉踩式对比 |

---

### 维度7：基础错误

- 产品名称、型号正确（参数密集，出错概率高于其他类型）
- 技术参数准确（对照 `product-knowledge.md`）
- 功能边界正确，无夸大
- 禁止词：科技/黑科技/神器/方案/智商税
- 标题是否命中搜索关键词（前10字内植入）

---

### 维度8：节奏与承接

- 场景、卖点、数据之间是否有自然过渡？
- 模块间是否有递进衔接而非断裂？
- 是否避免了重复、拖沓和突然跳转？
- 排除产品的后续处理：在排除维度后给收尾句，后续不再出现

---

## 三、评分等级

| 分数 | 等级 | 处理建议 |
|------|------|---------|
| 85+ | 可发 | 直接用，最多改几个字 |
| 70-84 | 润色 | 方向对，个别表述调一调 |
| 55-69 | 修改 | 有明显问题，但框架可保留 |
| <55 | 重写 | 核心问题多，需要重新构思 |
| <60 | 不合格 | 问题严重，需要大改或重写 |

每个维度在满分范围内直接打分（如满分15的维度，直接打0-15分）。总分 = 各维度得分之和，满分100。

单品测评取前 7 个维度（不含产品对比公平性），横测将诚实度替换为产品对比公平性。

## 四、Search · 深度评测 红线

| 序号 | 规则 |
|------|------|
| S-DR-1 | 全篇无槽点/无"不适合谁" → 诚实度直接降级 |
| S-DR-2 | 标题未命中目标搜索关键词 → 标记提醒 |
| S-DR-3 | 禁止贬低竞品（横测中可以说各自优劣，但不可拉踩） |
| S-DR-4 | 功能边界必须与产品实际能力匹配 |
| S-DR-5 | 禁止词：科技/黑科技/神器/方案/智商税 |

## 五、口播深度评测脚本·常见问题速查（47脚本实审提炼）

> 来源：2026年4-8月审核的47份真实达人口播脚本（SW音乐泳镜+H3/3Pro），提炼出高频出现的问题模式。审核时按此清单快速扫描。

### 结构类问题

| 问题 | 表现 | 处理 | 典型案例 |
|------|------|------|---------|
| 伪横测 | 开头摆多产品但后续只围绕主推品拆卖点 | 脚本结构+产品对比公平性双降级 | JMY影像小屋（摆3产品+标价但后续只讲SW） |
| 排除产品无交代 | 横测中排除一个产品后后续无任何提及 | 标注"排除产品衔接缺失" | 对比：小梦蓝牙段处理好（排除后给收尾句） |
| 功能堆砌无递进 | 用"第一/第二/第三"逐个罗列功能，无维度逻辑 | 建议改为由基础到体验的递进结构 | 大杰原版、兔小九 |
| 结尾无人群分层 | 只推荐主推品，不按需求分人群 | 必须有"适合谁/不适合谁" | 对比：小梦"岸上→水下凑合→水下高要求"三层推荐 |

### 表达类问题

| 问题 | 高频表现 | 出现频次 | 建议替换 |
|------|---------|---------|---------|
| 说明书腔 | "搭载XX传感器""支持XX功能""采用XX设计" | 8-10个脚本 | "靠XX识别…""可以XX""这个设计的好处是…" |
| 参数堆砌无体感 | 直接搬"IP68防水""9DoF传感器""4GB存储"无场景 | 5+个脚本 | 每个参数必须带使用场景："防水完全没问题，放心用" |
| 空洞感叹收尾 | 每段以"真的太香了""真的很好用"结尾 | 普遍 | 删掉或替换为具体使用感受 |
| "只能听个响" | 形容骨传导/开放式耳机时过于贬低 | 3个脚本 | "声音略散""音质一般"——客观描述不拉踩 |

### 卖点顺序审核要点

**SW音乐泳镜标准顺序**（从47个脚本中提炼的高频优先序）：
1. 水下听歌（情绪最强的一级卖点，占最大篇幅）
2. 语音数据播报（功能差异化，二级卖点）
3. 防雾/基础性能（泳镜本职，三级卖点）
4. 模块化可换+算账（成本收尾，固定在功能之后）
5. 人群推荐/不推荐（结尾分层）

**H3/3Pro标准顺序**：
1. AR实时数显（核心差异化，一级卖点）
2. 训练计划下发+跟练（功能深度，二级卖点）
3. 游后数据复盘（闭环价值，三级卖点）
4. 防雾/基础性能
5. 模块化可换
6. GPS/指南针（仅3Pro）
7. 人群推荐

> **审核标准：** 一级卖点必须最先出现且篇幅最重。如果二级卖点占了最多篇幅、一级卖点被弱化，种草顺序降分。

### 产品出场过渡·好坏对照

| 类型 | 好✅ | 差❌ |
|------|------|------|
| 装备累赘法 | "以前出门要带泳镜、耳机、手表、耳塞——现在一副搞定" | "这款产品功能很多" |
| 替代品痛点法 | "骨传导水下声音飘，手表要停下来看——这个都解决了" | "对比传统方案，优势明显" |
| 需求升级法 | "基础款够用了，但想坚持下来，得让自己游得更舒服" | "如果你想要更好的体验" |

### 对比竞品·边界把控

| 合格✅ | 踩线❌ |
|--------|--------|
| "手表是全能选手，泳镜是游泳专项选手"（给竞品合理定位） | "骨传导只能听个响而已"（过于主观负面） |
| "入耳式在水下音质更稳定，不会忽大忽小" | "骨传导在水里全是杂音" |
| "手表数据获取不够便利——要停下来看" | "手表在游泳时根本没用" |
