# gl-shenhe

这是一个轻量入口，避免 Claude Code 启动或恢复会话时一次性读取过多内容。

使用方式：
1. 先读取 `references/full-instructions.md`，了解审核体系总览、通用规则和输出格式。
2. **用户会告知内容类型**，根据用户指定的类型读取对应文件：

| 用户指定 | 读取文件 |
|---------|---------|
| Feeds · 标题正文（小红书笔记文案，被动刷到） | `type-feeds-标题正文.md` |
| Feeds · 脚本（信息流短视频，含镜头/画面） | `type-feeds-脚本.md` |
| Search · 标题正文（小红书笔记文案，主动搜索） | `type-search-标题正文.md` |
| Search · 脚本·深度评测（单品测评/横测/避雷攻略） | `type-search-深度评测.md` |
| Search · 使用分享（个人经历叙述，不区分标题正文/脚本） | `type-search-使用分享.md` |

3. 不要默认读取全部支撑文件。仅在当前任务确实需要时，按需读取：
   - `product-knowledge.md`：涉及具体产品参数、功能边界、禁忌红线时读取。
   - `examples.md`：需要参考案例时，按类型标签搜索相关片段，不要整文件读取。
   - `persona-standard.md`：只有做人感评分或人感表达优化时读取相关片段。
4. 若文件很长，优先搜索关键词或分段读取，避免触发上下文压缩。

## 审核体系总览

```
审核入口
├── Feeds（被动刷到 → 种草 → "让不想买的人想买"）
│   ├── 标题正文（小红书笔记文案）
│   └── 脚本（信息流短视频，含镜头/画面）
│
└── Search（主动搜索 → 决策 → "让想买的人买对"）
    ├── 标题正文（小红书笔记文案）
    ├── 脚本·深度评测（单品测评 / 横测 / 避雷攻略）
    └── 使用分享（个人经历叙述，不区分标题正文/脚本）
```

**Feeds vs Search 核心区别：**

| 维度 | Feeds | Search |
|------|-------|--------|
| 用户状态 | 被动刷到，没有明确需求，随时划走 | 主动搜索，带着问题来的，愿意花时间看 |
| 核心任务 | 种草——从0到1激发兴趣 | 决策——把已有兴趣转化为选择 |
| 内容本质 | 情绪驱动，让人"想要" | 信息驱动，帮人"选对" |
| 传递核心 | 人、情绪、体验 | 产品、功能、是否值得 |
| 标题逻辑 | 好奇心/情绪驱动，不放品牌名 | 必须命中搜索关键词 |
| 卖点策略 | 1-2个打透，场景化体验 | 3-5个系统拆解，数据说话 |
| 槽点/缺点 | 不需要 | 必须有——全正面=广告=不可信 |
| 广告感容忍 | 极低 | 较高 |
| 价格信息 | 禁止出现 | 可以有 |

**脚本 vs 标题正文 区分：**
- 脚本：包含镜头/画面描述、分镜、时长分配的拍摄脚本
- 标题正文：小红书笔记的标题+正文文案，无镜头描述

> ⚠️ 文案美化技巧（9种翻译技巧）仅适用于 **Feeds 类型**。Search 类型的信息密度和诚实度本身即是说服力，不套用情绪放大技巧。
