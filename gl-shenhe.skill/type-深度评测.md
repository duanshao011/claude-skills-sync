# 深度评测类审核指南

## 一、类型定义

**什么算深度评测：**
- 口播视频为主，通常60秒以上
- 有完整的结构（开头钩子→主体→总结→CTA）
- 对产品进行多维度拆解（功能、体验、对比、推荐）
- 包含横测对比、单品深度测评、避雷/选购攻略等子类型

**判断依据：** 脚本是否按"模块化结构"组织，是否有明确的评测维度或对比逻辑。

**深度评测的内容定位——搜索承接：**

深度评测本质是"搜索承接"内容——用户主动搜索"XX产品测评""XX对比""XX推荐"后看到的内容。与信息流完全不同：

| 维度 | 信息流（种草） | 深度评测（搜索承接） |
|------|--------------|-------------------|
| 用户状态 | 被动刷到，随时划走 | 主动搜索，带着问题来 |
| 核心任务 | 激发兴趣，从0到1种草 | 帮用户做决策，完成说服 |
| 信息密度 | 低——1-2个卖点打透 | 高——3-5个维度系统拆解 |
| 槽点/缺点 | 不需要 | **必须有**（全正面=广告=不可信） |
| 风格 | 情绪驱动，像朋友分享 | 信息驱动，像靠谱的过来人帮你做功课 |
| 标题 | 好奇心/情绪驱动 | 必须命中搜索关键词 |
| 价格 | 禁止出现 | 可以有算账逻辑 |

> **审核时的关键判断**：不要用信息流的"少即是多"标准来审评测。评测的信息密度高是对的，功能展开多是对的，时间长是对的——因为搜索用户就是来找这些信息的。

## 二、审核侧重（维度权重偏移）

| 维度 | 优先级 | 说明 |
|------|--------|------|
| 脚本结构 | ★★★ | 完整度是核心，模块逻辑必须清晰 |
| 产品种草顺序 | ★★★ | 卖点层级和递进逻辑决定说服力 |
| 种草深度 | ★★★ | 每个卖点需有场景/实测/数据支撑 |
| 口语化风格 | ★★ | 要求自然，但不是第一优先 |
| 基础错误检查 | ★★ | 参数密集，出错概率高 |
| 节奏与承接 | ★★ | 模块间过渡要顺 |
| 产品对比（仅横测） | ★★ | 对比公平性和维度选择 |
| 情感共鸣 | ★ | 达标即可，不强求 |

## 三、子类型模板

### 3.1 单品深度测评

**推荐结构：**
1. 开头钩子（0-7秒）— 痛点/疑问抓注意
2. 产品概览 — 一句话定位
3. 核心功能实测（2-3个维度逐个拆）
   - 维度顺序：最易感知优先
   - 每维度：场景描述 → 体验感受 → 数据佐证
4. 使用场景展开
5. 性价比/算账逻辑
6. 人群推荐 + 结尾CTA

**SW音乐泳镜单品测评（15模块版）：**

| 序号 | 模块 | 要点 |
|------|------|------|
| 1 | 开头抛问题 | 争议性问题切入，3-7秒抓注意力 |
| 2 | 评测维度预告 | 提前告诉观众测几个点，建立客观预期 |
| 3 | 水下听歌实测 | 第一核心卖点。必须带出：入耳式防水设计、离线播放、续航6小时 |
| 4 | 听歌真实结论（含槽点） | 真实局限 + 耳塞耳机二合一 |
| 5 | 语音播报实测 | 按趟播/按时间播两种模式，播报内容，中英文支持 |
| 6 | 播报功能结论（含槽点） | 实际价值 + 注意点 |
| 7 | 泳镜基础体验 | 73g、IP68、防雾涂层3年、近视200-600度、九轴传感器 |
| 8 | 基础体验结论（含槽点） | 佩戴感受 + 适应成本 |
| 9 | 游后数据复盘 | App同步、AI教练、周/月报、导出 |
| 10 | 数据复盘结论 | 普通用户够不够用 |
| 11 | 模块化可更换（成本收尾） | 【必须包含】镜片/胶圈/绑带免费换，位置在功能之后 |
| 12 | 人群定向——适合谁 | 3类人群明确 |
| 13 | 人群定向——不适合谁 | 【必须包含】全正面=广告感降级 |
| 14 | 价值拆解 | 算账式性价比 |
| 15 | 收尾总结 | 一句话核心印象 |

**关键规则：**
- 每个评测模块的「结论段」必须带一个真实槽点或使用注意
- 禁止词：「智商税」（含变体）、「方案」（商务腔）、「骨传导」（统一说入耳式防水耳机）

**常见问题：**
- 只讲听歌不讲播报，让人以为只是游泳耳机
- 忘了讲基础性能，用户觉得"功能多但泳镜本职不行"
- 全篇无槽点，广告感溢出，种草深度直接降级
- 模块化可更换未提及，缺少成本层说服
- 人群推荐只说适合谁不说不适合谁

### 3.2 横测对比

**适用场景：** 2款以上产品/方案横向对比

**推荐结构：**
1. 开头钩子 — 选择困难切入
2. 展示全部参评对象 — 说明对比维度
3. 逐维度对比（每个维度：逐一评价 → 结论）
   - 维度选型原则：由基础到体验递进
   - 每维度先说所有产品表现，再给结论
4. 排除产品的后续处理：在排除维度后给总结收尾，后续不再出现
5. 总结 + 按需求分层推荐
6. 结尾CTA

**横测结构核心检查点：**
- 维度间有递进逻辑（如防水→音质→便利性）
- 对比公正，不过度贬低竞品
- 被排除的竞品有合理交代
- 结尾有用户分层（不同需求推荐不同选择）
- **分维度对比段占全片50%以上**（这是横测的核心价值区）
- **必须给出明确推荐结论**——"都不错各有优劣"等于没说，搜索用户要的是答案

**行业标准横测时长分配参照：**

| 段落 | 时长占比 | 内容 |
|------|----------|------|
| 开场hook | 5% | "纠结了一周终于决定全买来试" |
| 产品一览 | 10-15% | 逐一简要介绍参与对比的产品 |
| **分维度对比** | **50-60%** | 从3-5个维度逐一对比，用统一标准 |
| 结果汇总 | 10-15% | 表格/图表展示各项评分 |
| 分场景推荐 | 5-10% | "训练为主选A，休闲为主选B" |

**"伪横测"识别标准：**

开头摆出多款产品，但后续没有按维度逐一对比，实质是单品测评。

| 维度 | 伪横测 ❌ | 真横测 ✅ |
|------|----------|----------|
| 开头 | 摆产品+标价，没说对比维度 | 明确说"从哪几个维度来聊" |
| 对比方式 | 围绕主推品拆卖点，竞品插入式吐槽 | 每维度逐一评价所有产品 |
| 产品公平性 | 部分产品几乎未参评 | 排除有明确交代 |
| 结尾 | 只推荐一个 | 按需求分层推荐 |

> 伪横测应降低"脚本结构"和"产品对比"两个维度评分。

### 3.3 避雷/选购攻略

**推荐结构：**
1. 开头钩子 — 千万别买错XX！
2. 踩雷款逐一介绍（具体问题+场景）
3. 引出推荐 — 自然过渡
4. 推荐产品核心卖点
5. 结尾CTA

**常见问题：**
- 踩雷部分太长，推荐部分太短（比例失衡）
- 踩雷描述不够具体
- 引出推荐太生硬

## 三-B、深度评测专属红线

| 序号 | 规则 | 原因 |
|------|------|------|
| 评测-1 | **全篇无槽点/无"不适合谁"** → 红线命中 | 搜索用户在做决策，全正面=广告=不可信。种草深度直接降一档 |
| 评测-2 | **标题未命中目标搜索关键词** → 标记提醒 | 搜索承接内容的标题决定能否被搜到，标题无关键词=白做 |

## 三-C、标题审核（搜索承接专用）

深度评测的标题服务于搜索——用户搜什么词，标题里就要有什么词。

**搜索承接标题公式**：`[品牌/品类词] + [使用场景/人群] + [核心价值]`

**好标题 vs 坏标题：**

| ✅ 好标题（命中搜索词） | ❌ 坏标题（搜不到） |
|----------------------|-------------------|
| 光粒Holoswim 3智能泳镜｜用了三个月的真实感受 | 这副泳镜改变了我的游泳方式 |
| 5款智能泳镜横测｜游泳爱好者实测对比 | 到底买哪个？全部买来试了！ |
| 近视也能用的智能泳镜｜200-600度定制方案实测 | 近视人的福音来了 |
| 光粒SollaWave音乐泳镜深度测评｜游泳听歌真实体验 | 泳池里的音乐时间 |

**关键词分层参考**：
- 品牌词（精搜用户）："光粒泳镜 测评""SollaWave 评测"
- 品类词（高潜用户）："智能泳镜 推荐""游泳耳机 哪个好"
- 场景词（泛用户）："游泳装备推荐""一个人游泳怎么练"

> 标题前10字内必须植入核心搜索词。标题长度18-20字最佳。

## 四、通用审核规则（跨子类型适用）

### 规则1：多功能产品不贴负面标签

不能用"胡里花哨""噱头""华而不实"让观众先否定产品再反转。正确逻辑：多功能是卖点，基础性能是加分——"功能这么多，基本功反而更强"。

> ✅ 你可能会想，功能这么多，防水防雾能行吗？放心，这块它反而做得更好
> ❌ 有人认为这些都是胡里花哨的东西，泳镜最主要就是防水，看得清！

### 规则2：欲扬先抑的"抑"不能指向产品

"抑"的对象应该是事情本身（游泳难、训练苦），不能是产品效果。

> ✅ 游泳这件事没有捷径，但一副好的装备，能让你在训练的过程中更加得心应手
> ❌ 这样的泳镜，不一定会让你游的更好

### 规则3：功能边界必须交叉验证使用场景

脚本中的每个使用场景要与产品实际能力匹配。

| 产品 | 不支持的场景 |
|------|------------|
| SW | 公开水域/铁三（无GPS） |
| SW | 替代运动手表（仅横测禁忌，防拉踩；单品深度评测可用） |

### 规则4：耗材可换段落的最佳位置

放在"值得买/值得投资"结论之后，作为"买了还能用很久"的补充论据。不要插在功能拆解中间。

## 五、常见问题速查

| 问题 | 影响维度 | 处理 |
|------|---------|------|
| 维度间缺乏递进 | 脚本结构 | 建议调整维度顺序，由基础到体验 |
| 对比不公平 | 产品对比 | 标注，给竞品合理定位 |
| 卖点平铺无主次 | 种草顺序 | 建议一级/二级/三级排序 |
| 全篇无槽点 | 种草深度 | 直接降级，标注"广告感" |
| 参数张冠李戴 | 基础错误 | 对照产品库逐一验证 |
| 排除品后续断裂 | 脚本结构 | 建议在排除维度后给收尾句 |
