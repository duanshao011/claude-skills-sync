# Feeds · 脚本审核指南

## 一、类型定义

**什么算 Feeds · 脚本：**
- 信息流短视频拍摄脚本，含镜头/画面描述、分镜、时长分配
- 投放在信息流广告位（抖音/小红书信息流）
- 用户被动刷到，随时划走，前3秒决定生死
- 核心任务：情绪种草——让不想买的人想买
- 传递核心：人、情绪、体验
- 总时长建议 40-60 秒
- **不出现价格/优惠信息**（种草不拔草）

**与 Search · 深度评测的核心区别：**

| 维度 | Feeds · 脚本 | Search · 深度评测 |
|------|-------------|------------------|
| 时长 | 40-60秒 | 2-5分钟 |
| 用户状态 | 被动刷到，随时划走 | 主动搜索，带着问题来 |
| 卖点数量 | 1-2个打透 | 3-5个系统拆解 |
| 审核重心 | 文案表达+种草深度 | 脚本结构+种草深度 |
| 槽点/缺点 | 不需要 | 必须有 |
| 价格 | 禁止出现 | 可以有 |

---

## 二、审核维度（5维度）

| 维度 | 满分 | 核心问题 |
|------|------|---------|
| 脚本结构 | 25 | 7段式结构完整吗？Hook有没有？核心卖点段占全片1/3+？ |
| 种草深度 | 25 | 1-2个核心功能有没有打透？场景+体验+情绪三层都有？ |
| 文案表达 | 25 | 像真人在分享日常还是品牌方念稿？卖点有没有翻译成体验？ |
| 基础错误 | 15 | 参数准确、无禁止词、品牌名延后、无价格 |
| 画面匹配 | 10 | 镜头描述和文案是否匹配？画面有没有强化情绪？ |

---

### 维度1：脚本结构（25%）

**审核核心问题：脚本是否有清晰的节奏线，而非功能堆砌？**

| 分数 | 特征 |
|------|------|
| 9-10 | 7段式结构完整，时长分配合理，节奏有起伏 |
| 7-8 | 结构基本完整，个别段偏长或偏短 |
| 5-6 | 有结构但节奏不好，某段过重或缺失 |
| 3-4 | 结构混乱，像评测删减版 |
| 1-2 | 无结构，功能堆砌 |

**7段式结构要求：**
1. Hook（3-5s）— 场景代入，必须有人/场景/动作，禁止纯产品特写开头
2. 痛点+产品出场（5-8s）— 一句话痛点 + 自然佩戴画面
3. 核心卖点打透（15-20s）★ — 占全片1/3以上
4. 次要功能（5-8s）— 自然穿插，不停下来单独讲
5. 节奏转折（3-5s）— 动态画面过渡
6. 收尾数据/感受（5-8s）— 成就感/变化感
7. 轻种草收尾（3-5s）— 加分项一句带过

**审核要点：**
- Hook 是否避开纯产品特写？
- 核心卖点段时长是否占全片1/3以上？
- 非核心功能是否控制在"一句话"以内？
- 总时长是否在40-60秒范围？
- 脚本方向是否匹配产品和受众（痛点直述/效果表达/人群锚定/悬念揭秘/塑造情绪）？
- 加分项（防雾/近视/续航等）是否放在收尾而非前置？

---

### 维度2：种草深度（25%）

**审核核心问题：是否有1-2个功能被"打透"了，而非每个功能都浅尝辄止？**

> 信息流是减法——砍到只剩1-2个核心体验，其他一句带过。"都是卖点=没有卖点"。

| 分数 | 特征 |
|------|------|
| 9-10 | 只聚焦1-2个核心功能，有场景+体验+情绪三层打透，其他一句带过 |
| 7-8 | 重点有足够篇幅和体验细节，主次分明 |
| 5-6 | 有重点但不够深，或非核心展开过多挤占核心段时长 |
| 3-4 | 每个功能都提了但都浅，像功能清单 |
| 1-2 | 纯功能罗列，无场景无体验 |

**审核要点：**
- 1-2个功能获得重点篇幅（占全片1/3以上）？
- 重点功能有场景描写+体验感受，而非只说"有这个功能"？
- 非重点功能是否控制在"一句话"以内？
- 是否避免了评测式硬核讲解（拆参数、逐项打分）？
- **禁止出现价格/优惠信息**
- **场景化检测**：卖点有没有落到具体场景里（什么时间、什么地方、做什么动作时用到）？只说"支持XX功能"而没有场景=没打透。行业数据：痛点细节占比>40%时收藏率提升2.3倍

---

### 维度3：文案表达（25%）

**审核核心问题：像真人在分享日常，还是品牌方在念稿？卖点是否翻译成了体验？**

| 分数 | 特征 |
|------|------|
| 9-10 | 有个人语言特征，情绪感染力强。所有功能用"我在用的瞬间"表达 |
| 7-8 | 像真人说话，有情绪价值，大部分卖点已转化为体验 |
| 5-6 | 部分自然部分广告腔，一会儿像分享一会儿像念参数 |
| 3-4 | 功能描述+感叹词组合，卖点基本没翻译 |
| 1-2 | 说明书/品牌稿直接读，"搭载XX技术""支持XX功能"贯穿全文 |

**审核要点：**
- 以个人体验和情绪价值为主线？
- 卖点是否翻译成了体验？（核心判断：在说"我用起来怎么样"还是"它有什么功能"）
- 是否有"我"的视角和感受？
- 模板词检查：宝藏/闭眼入/超顶等，2个以上扣分

**文案美化技巧（Feeds 脚本专用）：**

| 技巧 | 方法 | ❌ 说明书式 → ✅ 体验式 |
|------|------|----------------------|
| 场景强化 | 抽象卖点赋予画面感 | "支持实时数据显示"→"边游边看配速，不用停下来翻手表" |
| 多用数字 | 具体数字替代形容词 | "续航很长"→"游一整天都够用，室内16个小时" |
| 巧用比喻 | 用熟悉事物类比 | "内置训练计划"→"真的很像把私教戴在脸上" |
| 变化感对比 | 前后对比+数字展示改变 | "游泳更有效率"→"以前游500米就想上岸，现在1000米停不下来" |
| 寻物类比 | 具象事物替代抽象参数 | "73g"→"比一颗鸡蛋还轻" |
| 简单复杂化 | 简单功能赋予情感层次 | "纳米可擦拭防雾"→"游了一个小时还是清清楚楚" |
| 复杂简单化 | 复杂参数通俗化 | "600nit亮度"→"大太阳底下也看得清清楚楚" |
| 贩卖焦虑 | 放大不用产品时的痛点 | "帮助记录数据"→"游了半小时不知道游了多远" |
| 锚点借势 | 与已知概念关联 | "训练计划下发"→"相当于游泳版的Keep" |

> ⚠️ 技巧是放大器不是遮羞布。全文技巧密度高但读完不知道产品能干嘛 → 种草深度直接扣分。

### 维度4：基础错误（15%）

- 产品名称、型号正确
- 技术参数准确（对照 `product-knowledge.md`）
- 功能边界正确，无夸大
- 品牌名延后到后50%
- **不出现价格/优惠信息**
- 禁止词：科技/黑科技/神器/方案/智商税
- 话题标签齐全

---

### 维度5：画面匹配（10%）

**审核核心问题：镜头描述和文案是否匹配？画面是在强化情绪还是单纯展示产品？**

| 分数 | 特征 |
|------|------|
| 9-10 | 画面和文案情绪同频，镜头有节奏变化（全景/特写/第一视角切换），画面本身在讲故事 |
| 7-8 | 画面和文案基本匹配，但镜头单一或部分段落画面只是在"配图" |
| 5-6 | 画面跟随文案但无加分，类似幻灯片配画面 |
| 3-4 | 多段画面和文案脱节，或画面纯产品展示无场景 |
| 1-2 | 无镜头描述，或镜头描述与文案完全无关 |

**审核要点：**
- AR数显/第一视角画面是否清晰完整、时长充足？
- 关键体验段落是否有对应的强化画面（不是纯口播+泳池背景）？
- 画面是否有节奏变化（水下/水面/第一视角/手机录屏画中画）？
- 收尾画面是否自然（手持手机+泳池背景，非纯录屏）？

## 三、评分等级

| 分数 | 等级 | 处理建议 |
|------|------|---------|
| 85+ | 可发 | 直接用，最多改几个字 |
| 70-84 | 润色 | 方向对，个别表述调一调 |
| 55-69 | 修改 | 有明显问题，但框架可保留 |
| <55 | 重写 | 核心问题多，需要重新构思 |

每个维度在满分范围内直接打分（如满分25的维度，直接打0-25分）。总分 = 各维度得分之和，满分100。

## 四、Feeds · 脚本 红线

| 序号 | 规则 |
|------|------|
| F-SC-1 | Hook 禁止纯产品特写开头，必须有人/场景/动作 |
| F-SC-2 | 核心卖点段时长必须占全片1/3以上 |
| F-SC-3 | 封面和正片严禁纯身材/泳衣擦边镜头 |
| F-SC-4 | 字幕不要和画面内容重叠，底部留出平台交互栏空间 |
| F-SC-5 | 全片语气像"游泳爱好者分享日常"，不像"产品介绍" |
| F-SC-6 | 功能种草画面需有字幕或口播，不能只有游泳画面无信息 |
| F-SC-7 | 禁止出现价格/优惠信息 |
| F-SC-8 | 品牌名延后到后50% |
