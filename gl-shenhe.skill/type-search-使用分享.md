# Search · 使用分享 审核指南

## 一、类型定义

**什么算 Search · 使用分享：**
- 以个人真实使用经历为主线的笔记或视频脚本
- 重点是"我用了之后经历了什么"，不是"这个产品有什么功能"
- 不追求评测的完整度和模块化结构，可以只聊1-2个核心体验
- 用户主动搜索"XX体验""用了XX之后"看到
- **不区分标题正文和脚本**——图文笔记和口播视频用同一套审核标准

**与 Search · 深度评测的核心区别：**

| 维度 | 深度评测 | 使用分享 |
|------|---------|---------|
| 视角 | 评测者/KOL，做功课给别人看 | 真实用户，讲自己的经历 |
| 结构 | 模块化、完整覆盖 | 经历线、可以只聊1-2个点 |
| 信任来源 | 专业性+客观性 | 真实感+共情 |
| 卖点密度 | 高，系统拆解 | 低，围绕核心体验展开 |
| 槽点要求 | 每模块带一个 | 整体有诚实评价即可 |

> ⚠️ 文案美化技巧（场景强化/贩卖焦虑/夸张等）**不适用于 Search 类型**。使用分享的真实感来自诚实和具体细节，不是来自技巧渲染。技巧用多了反而破坏"真人分享"的感觉。

---

## 二、审核维度（5维度）

| 维度 | 占比 | 核心问题 |
|------|------|---------|
| 人感真实度 | 20% | 看完觉得像不像一个真人在分享自己的经历？有"我"的身份/经历/判断/口语节奏吗？ |
| 诚实信任度 | 20% | 有没有说缺点/不适合谁/犹豫过程？全篇夸=不可信 |
| 体验故事性 | 20% | 有没有"之前vs现在"的变化弧线？还是功能罗列+感慨？ |
| 种草说服力 | 20% | 看完想不想买？靠场景细节驱动，不靠形容词堆砌 |
| 基础错误 | 20% | 参数准确、无禁止词 |

---

### 维度1：人感真实度（30%）

**核心判断：这篇内容像不像一个真实的人在分享自己的真实经历？**

| 分数段 | 特征 |
|--------|------|
| 9-10 | 有鲜明的"我"的身份设定（如"每周泡三次泳池的游泳爱好者"），口语节奏自然，有个人判断和态度，听完能描绘出这是个什么样的人 |
| 7-8 | 有"I"视角但身份设定比较泛（"游泳爱好者"），整体自然但缺乏鲜明的个人特征 |
| 5-6 | 有"我"但更像是功能体验的载体——"我用了功能A，感觉很X；我用了功能B，感觉很Y"，人没有独立于产品的故事 |
| 3-4 | 第三人称介绍感强，偶尔插入"我觉得"，本质还是产品介绍 |
| 1-2 | 品牌稿/说明书，无人感 |

**合格信号：**
- 开头有"我"的身份设定（不一定要标签化，但要让人知道"谁在说话"）
- 有从怀疑到尝试的心理过程（"又是噱头吧"→"试了一下发现不太一样"）
- 有具体数字和个人细节（"游了三个月，每周两次"比"用了很久"可信十倍）
- 有场景细节（"自由泳转头换气的时候，余光扫到配速变了"）
- 口语化但有内容，不是空洞感叹

**不合格信号：**
- 开头用"想问各位云搭子们…"/"泳搭子们"自问自答套路
- 空洞感叹词："真香啊""打开新世界的大门""救大命""极简星人狂喜"
- 功能罗列+感叹："1个装备顶5个""二合一设计""IP68深潜级防水""一副搞定"
- 每个卖点独立出现、无关联，像产品页拆散了重排
- 缺少真实心理转变过程

---

### 维度2：诚实信任度（25%）

**核心判断：这个人是在帮同类用户做参考，还是在推销？**

| 分数段 | 特征 |
|--------|------|
| 9-10 | 主动说缺点/使用注意/"不适合谁"，有犹豫和权衡的过程，结论诚实不夸大 |
| 7-8 | 有诚实评价但比较轻（"除了XX稍微弱一点，其他都不错"），或"不适合谁"比较笼统 |
| 5-6 | 提到了一点不足但轻描淡写，整体还是强烈推荐腔 |
| 3-4 | 全篇正面，无任何槽点或限制说明 → **红线命中** |
| 1-2 | 纯广告稿 |

**审核要点：**
- 有没有主动说缺点？（必须是用户真的会在意的点，不是"包装盒有点难拆"这种假槽点）
- 有没有说"不适合谁"？（"纯休闲泡水没必要买"比"大家根据需求选择"具体得多）
- 推荐语气是否克制？（"想提升训练质量的可以试试"比"一定要买！"可信得多）
- 使用时长/频次是否明确？（"用了三个月"比"买了一段时间"可信）

---

### 维度3：体验故事性（20%）

**核心判断：有没有"之前vs现在"的变化弧线？**

| 分数段 | 特征 |
|--------|------|
| 9-10 | 有完整的经历弧线（之前什么状态→为什么想试→试用中的发现→现在的结论），变化感清晰 |
| 7-8 | 有变化对比但不连续，或弧线不够完整 |
| 5-6 | 有"之前"但很泛（"以前游泳很无聊"），变化感不够具体 |
| 3-4 | 功能罗列，每个功能配一句感受，无先后变化 |
| 1-2 | 纯功能清单 |

**合格特征（具体的"之前vs现在"）：**
- "以前每次游到500米就开始数还剩几趟，越数越不想游 → 后来换了这个，游着游着一首歌没听完就过了1000米"
- "之前练打腿最烦的是手表老漏记圈数，一度不想练 → 换了之后转身不漏圈，终于肯练打腿了"
- "之前看数据要切仰泳瞟一眼手表再翻回来，配速直接掉 → 现在余光扫一眼镜片就有了"

**差信号：**
- 之前很泛（"以前游泳体验不好"）+ 之后很广告（"有了XX之后一切都变了"）
- 缺少中间的"尝试/发现"环节，直接从"以前"跳到"现在"
- 变化感全靠形容词（"太爽了""太方便了"）而非具体对比

---

### 维度4：种草说服力（15%）

**核心判断：看完之后想不想买？靠场景细节驱动还是形容词堆砌？**

| 分数段 | 特征 |
|--------|------|
| 9-10 | 看完觉得"如果我也是这类人，这东西确实有用"，被具体的场景和使用细节说服 |
| 7-8 | 有说服力但部分卖点靠形容词或感叹驱动 |
| 5-6 | 有打动人的点但被广告腔稀释了说服力 |
| 3-4 | 看完记不住任何具体的场景或使用细节，只记得"好用" |
| 1-2 | 零说服力，看完只觉得是广告 |

**审核要点：**
- 说服力来自具体细节还是堆砌形容词？
- 有没有让读者产生"这说的就是我"的代入感？
- 核心卖点有没有落到实际使用场景里（不是"功能强大"，是"什么时候用、用了什么感觉"）？

---

### 维度5：基础错误（10%）

- 产品名称、型号正确
- 技术参数准确（使用分享不像评测那样参数密集，但出现的数字必须准确）
- 功能边界正确，无夸大
- 禁止词：科技/黑科技/神器/方案/智商税
- 标题含搜索关键词（使用分享可以比深度评测标题更偏人感，但核心搜索词不能丢）

## 三、评分等级

| 分数 | 等级 | 含义 |
|------|------|------|
| 85+ | 优秀 | 真实可信，看完觉得这就是一个真实用户会说的话 |
| 70-84 | 良好 | 方向对，个别地方广告腔或空洞感叹需要替换 |
| 60-69 | 需优化 | 人感和诚实度不足，读起来像功能清单+个人感受拼贴 |
| <60 | 重写 | 广告感严重或无真实经历痕迹 |

维度评分 1-100 分。"得分"列 = 维度分值 × 占比。总计 = 各维度得分之和（百分制）。

## 四、Search · 使用分享 红线

| 序号 | 规则 |
|------|------|
| S-US-1 | 全篇无槽点/无"不适合谁" → 诚实信任度直接降级 |
| S-US-2 | 空洞感叹词超过3处（真香/打开新世界/救大命/狂喜等）→ 人感真实度降级 |
| S-US-3 | 功能罗列+感叹结构（每个功能独立成段+每段以感叹收尾）→ 体验故事性降级 |
| S-US-4 | 禁止词：科技/黑科技/神器/方案/智商税 |
| S-US-5 | 标题需含搜索关键词（比深度评测可偏人感，但不能像Feeds那样完全无搜索词） |

## 五、合格 vs 不合格 特征速查

### ✅ 合格的特征
- 开头有"我"的身份设定（如"每周泡三次泳池的游泳爱好者"）
- 有从怀疑到尝试的心理过程（如"又是噱头吧"→"试了一下发现不太一样"）
- 有具体数字和对比（"游了三个月，每周两次，续航一周充一次足够"）
- 有场景细节（"自由泳转头换气、翻滚转身都不晃"）
- 口语化但有内容（不是空洞感叹"真香啊"）
- 主动说缺点建立信任（"低频稍弱""差点没听见救生员哨声"）
- 推荐语气克制（"想提升训练质量的可以试试"）

### ❌ 不合格的特征
- 开头用"想问各位云搭子们…""泳搭子们"自问自答套路
- 空洞感叹词："真香啊""打开新世界的大门""救大命""极简星人狂喜"
- 功能罗列+感叹："1个装备顶5个""二合一设计""IP68深潜级防水""一副搞定"
- 缺少真实心理转变过程，直接从"以前不好"跳到"现在真香"
- 每个卖点独立出现、无关联，像产品页拆散了重排
- 全篇正面无槽点

## 六、推荐结构（选路不填空）

> **核心理念：模板管"必须覆盖哪些信息"，不管"用什么姿势覆盖"。** 每个节点给多条人格入口，达人按自己的风格选路走，不要求所有节点都出现。

### 节点属性说明

| 标记 | 含义 |
|------|------|
| 🔴 必选 | 必须出现，但可从多条人格入口中选一条 |
| 🟡 可选 | 有真实素材就写，硬编反而假，跳过不扣分 |
| 🟢 加分 | 出现加分，不出现不扣分 |

### 完整结构

| 序号 | 节点 | 性质 | 人格入口（选最像自己的） | 表达式参考 |
|------|------|------|------------------------|-----------|
| 1 | 身份设定 | 🔴 必选 | 数据控 / 无聊劝退 / 装备党 / 佛系养生 / 痛点驱动 | `persona-standard.md` 条目1 |
| 2 | 购买决策 | 🟡 可选 | 观望型 / 对比型 / 踩坑型 | `persona-standard.md` 条目2 |
| 3 | 痛点引入 | 🔴 必选 | 数据盲区 / 打断节奏 / 装备繁琐（三选一） | `persona-standard.md` 条目3 |
| 4 | 核心体验展开 | 🔴 必选 | AR显示体验 / 滚翻识别对比 / 训练计划跟练（聚焦1-2个） | `persona-standard.md` 条目4-5 |
| 5 | 加分项简述 | 🟢 加分 | 防雾 / 近视方案 / 续航（选1个有真实感受的，一句带过） | `persona-standard.md` 条目6 |
| 6 | 诚实吐槽 | 🔴 必选 | 价格 / 配件缺失 / 使用门槛 / 设计取舍（必须写自己真在意的点） | `persona-standard.md` 条目7 |
| 7 | 模块化收�� | 🔴 必选 | 算账型 / 省心型 / 对比型（固定在功能之后、结尾之前） | `persona-standard.md` 条目8 |
| 8 | 结尾CTA | 🟡 可选 | 互动型 / 推荐型 / 自然收尾型（不喜欢互动的删掉更自然） | `persona-standard.md` 条目9 |

### 使用原则

1. **达人选路，不填空。** 给达人看每个人格入口的描述，让他挑最像自己的。不要替他选。
2. **不要全部节点都出现。** 可选项跳过不扣分，凑数反而削弱真实感。博哥SollaWave案例中达人主动删了CTA、换了结尾，定稿比照单全收更自然。
3. **诚实吐槽是底线。** 没有这个节点的使用分享直接红线（S-US-1），写成假槽点同样降级。
4. **段落顺序不强制。** 购买决策可以放在痛点之前，也可以作为功能讲完后的呼应。按达人自己的叙事节奏来，只要逻辑线不跳就行。

### 模板痕迹检测（审核时快速扫描）

出现以下信号2个以上，标注"模板化风险"，人感真实度降一档：

| 信号 | 说明 |
|------|------|
| "作为一个XX爱好者" | 万能开头句，千篇一律 |
| "先说说/再说说/最后说说" | 元叙事句式，像在列提纲 |
| 每段长度均匀 | 像填空题，不符合真实叙事节奏 |
| "总结一下/总的来说" | 作文腔收尾 |
| 所有卖点段用同一句式开头 | "它最XX的是……""另外还要夸夸……" |
| 空洞感叹词收尾（真香/绝了/冲/太爱了） | 没有具体信息量的收尾 |

### 原口播推荐结构（保留参考）

**口播使用分享：**
1. 开头钩子 — 疑问句/经历切入
2. 痛点经历 — 之前用过什么、踩过什么坑（具体设备+具体问题）
3. 核心体验展开 — 围绕最核心卖点深入（体验为主，参数为辅）
4. 功能对比 — 对比替代品，讲体验差异不贬低
5. 加分项简述 — 不展开，一两句带过
6. 诚实评价 — 先说缺点/不适合谁，再说适合谁
7. 人群推荐 — 分类列出

- 重视开头和结尾，中间可以"散"一点
- 结构和口播遵循相同的5维度审核标准
