# 准星

本地信息源监控阅读器，聚合关注博主的最新内容。支持 YouTube、公众号、抖音、小红书、B 站等渠道。

## 使用方式

1. 运行 `scripts/open-zhunxing.ps1`（Windows 启动脚本）
2. 脚本自动检查 `http://localhost:3000` 是否可访问
3. 未启动则自动在后台拉起服务
4. 用默认浏览器打开页面

## 页面功能

- **三栏阅读器**：左侧博主/主题导航 → 中间文章列表 → 右侧内容预览
- **YouTube 视频嵌入**：直接在页面内播放
- **AI 摘要**：打开文章自动生成三段式结构化摘要（基于正文，DeepSeek 驱动，需配置 DEEPSEEK_API_KEY）

## 首次使用

1. 启动后在浏览器中点击「+ 添加博主」
2. 选择 YouTube，粘贴频道 URL（例如 `https://www.youtube.com/@Fireship`）
3. 点击验证，确认后添加
4. 系统自动抓取该频道最近视频
5. 如需 AI 摘要：复制 `app/.env.example` 为 `app/.env`，填入 API Key

## 配置

- 端口：默认 3000，可在 `.env` 中设置 `PORT=xxxx`
- AI 摘要：在 `app/.env` 中配置 DeepSeek 三件套（AI 摘要/翻译都用它）
  - `DEEPSEEK_API_KEY=sk-xxx`（必填，无则不生成摘要）
  - `DEEPSEEK_BASE_URL=https://api.deepseek.com`
  - `DEEPSEEK_MODEL=deepseek-chat`（解析为 v4 flash）
- 公众号/抖音等国内渠道：在 `app/.env` 中配置 `REDFOX_API_KEY`（RedFox 数据源）
- 定时抓取：每天 06:00 自动运行
- 数据文件：`app/data/feeds.db`（SQLite）

## 数据更新机制（重要）

各渠道数据来自第三方源，**不是实时的**，有固定延迟：

- **YouTube**：RSS 源，YouTube 更新后立即可用
- **公众号（RedFox）**：RedFox 每晚约 00:30 统一收录当天的文章，**最多滞后约 16 小时**——当天发文次日凌晨才能查到。若某号最新文章停留在几天前，通常是该号本身断更，不是准星漏抓
- **抖音/小红书/B 站（RedFox）**：同理有收录延迟，未实时

排查"为什么没抓到最新内容"时，先按此判断是数据源滞后还是真断更，不要误判为准星 bug。

## 公众号添加流程（搜索 → 确认 → 入库）

1. 「+ 添加信息源」→ 选「公众号」→ 输入公众号名称 → 点「搜索」
2. 弹出候选账号卡片（昵称 + 占位头像 + 微信号 + 认证），点击选中
3. 点「添加」→ 系统先验证该号是否被 RedFox 收录，**收录才入库**
4. 未被收录的号（RedFox「优质库」覆盖有限）会明确提示「RedFox 未收录该公众号」，不会静默失败

## 详情页阅读体验（公众号）

打开一篇文章时，右侧详情页从上到下：

1. **标题 + 发布时间 + 描述**
2. **AI 摘要**（自动生成，三段式：讲什么/为什么/有什么用；生成过则缓存秒出；进度条提示生成中）
3. **原文正文**（自动加载全文，按段落排版）

顶部右侧「原文」按钮 → 跳转微信原文链接（新标签页）。

### 正文清洗（重要，RedFox 数据源特性）

RedFox 返回的公众号正文有两点需要处理：

- **段落用连续空格分隔**，不是换行 → 按「6 个以上连续空格或换行」切分段落（阈值太低会把句子切碎）
- **文末混有固定推广/署名话术** → 用精确模板匹配剔除（如「我们正在招募伙伴」「📮 简历投递邮箱」「@ 作者 / xxx」「感谢你看到这里…点赞在看转发」等），只影响展示不改库

### AI 摘要技术实现

- 模型：DeepSeek（`deepseek-chat`，v4 flash），OpenAI 兼容接口 `POST {BASE_URL}/chat/completions`
- 公众号摘要基于**正文全文**生成；RedFox 无正文的文章降级为「基于标题和摘要生成」并标注
- 摘要生成后存入 `articles.ai_summary`，二次打开直接读缓存，不重复消耗 API
- 存量文章需 `work_uuid` 才能查正文：新抓取自动带，旧的刷新一次信息源即补全
