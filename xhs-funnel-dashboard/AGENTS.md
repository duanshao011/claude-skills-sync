# 投放看板项目维护规则

## 目标与边界

- 本目录是投放看板的主维护源码，所有功能修改先落在这里。
- 原始 Excel/CSV 只读，不在构建或验证过程中改写。
- 数据口径、图表交互和页面样式必须分别验证，不能只确认页面能打开。

## 跨 Agent 默认分工与读取顺序

- 本文件与同目录 `SKILL.md` 是 Codex、Claude Code（CC）共同加载的全局契约；不得把稳定业务逻辑只写进某个 Agent 的个人全局配置。
- Codex 默认负责看板开发：规则文档先行、主源码实现、测试、浏览器验证和正式成品安全更新。
- CC 默认负责数据加载：读取本文件和 `SKILL.md`，核对真实报表、运行 `scripts/build_dashboard.py`、验证正式成品并输出统一回执；日常刷新不得改源码或手工改生成 HTML。
- 用户明确指定时可以覆盖默认分工，但原始表只读、正式成品先备份、验证失败不得交付等规则不变。
- 所有 Agent 开工前固定读取：最近层级 `AGENTS.md` → 本文件 → `SKILL.md` → 数据目录的《看板目录规范》和各平台《报表更新说明》。

## 小红书双渠道成本硬口径

- 进店、加购、成交、GMV唯一采用淘宝星河；蒲公英、薯条、聚光中的近似转化字段不得替代。
- 全量投入 = 薯条实际支付 + 聚光实际消耗；顶部总投入展示全量，渠道金额必须可拆分。
- ROI与阅读/进店/加购/成交成本只使用星河可匹配笔记，并从每篇笔记首个付费日开始、统一截止星河最新日；晚于星河的数据进入“等待归因金额”。
- 表格只拆渠道金额和渠道天数，不计算渠道级ROI或渠道级进店成本，避免重复使用同一份星河分母。
- `spend` 继续作为两渠道合计金额；同时保留 `chili_spend`、`juguang_spend`，禁止再把 `spend` 解释为薯条单渠道金额。

## B站双渠道成本硬口径

- B站后端播放、进店、加购、成交、GMV唯一采用B站淘宝星河表。
- 三联按BVID匹配星河；必火没有内容ID，只能将“被投昵称”规范化后匹配星河达人昵称。
- 必火昵称必须在星河中一对一对应唯一BVID；未命中或一对多时禁止分摊金额，必须进入质量提示。
- B站全量投入 = 必火推广完成订单消耗金额 + 三联总花费；成本和ROI从每条内容首个付费日开始，统一截止星河最新日。
- 必火没有逐日消耗，整单金额按“推广开始日”归集；禁止平均拆分24/72小时订单，前端必须注明这是订单启动日近似口径。
- 当前B站范围只维护数据源、日维度进店、单篇趋势、单篇成本三张图；未经用户另行要求，不新增B站全链路明细表。

## CC 数据刷新统一回执

- 五个小红书数据源的文件名、加载状态、行数和日期范围：蒲公英、淘宝星河、薯条、聚光、灵犀。
- 全量投入、薯条实付、聚光实际消耗、星河截止日、等待归因金额。
- 薯条投放笔记数、聚光投放笔记数、双渠道笔记数、付费笔记并集、星河同样本命中数和未命中金额。
- 总GMV、同样本有效成本、整体ROI，以及 `scripts/cdp_check.py` 最终 PASS/FAIL。

## Git 版本管理

- `D:\Project\data-dashboard\skill` 是唯一 Git 主仓库和源码事实源；两个 Skill 镜像是发布副本，不单独初始化 Git。
- Git 只管理源码、测试、规则和维护文档。原始 Excel/CSV、正式成品、时间戳备份、浏览器验证配置、缓存、日志和验证截图不得提交。
- `main` 只保留经过检查的稳定版本。一个明确功能对应一个分支和一组聚焦提交，禁止把多个平台的无关修改混在同一提交中。
- 并行任务只有在修改边界清楚时才使用 Worktree；不同 Worktree 不得同时覆盖正式成品，合并回 `main` 后统一构建、验证和发布。
- 每次提交前必须查看变更清单和差异，确认没有报表、绝对数据路径、密钥、Token、浏览器资料或生成缓存进入版本历史。
- 回退优先使用新提交恢复指定文件或撤销指定提交；禁止用 `git reset --hard` 绕过检查。`git push`、历史改写和远程发布必须先获得用户明确许可。
- Git 版本管理不能替代正式成品的时间戳备份；覆盖 `全链路投放看板.html` 前仍须按“正式更新”流程备份和验证。

## 修改规则

- 修改前先确认需求属于数据加载、指标计算、前端交互或视觉样式中的哪一层。
- 自动扫描优先按 `01-小红书`、`02-抖音`、`03-B站` 子目录判定平台，文件名关键字只用于判定该平台内的数据源；根目录及其他位置继续按文件名关键字兼容识别。
- `03-B站` 内文件名含“星河”或“小红星”的表均归入B站星河，允许多份合并，并按 `(BVID, 日期)` 后传覆盖。
- 修改源文件后，同步受影响的两个 Skill 镜像；禁止只改生成后的 HTML。
- 新增或调整稳定业务契约时，同步更新 `SKILL.md`。
- 文件名、数据周期和数据源路径必须从 payload 动态读取，禁止硬编码当前批次名称。
- 不修改旧独立看板；统一成品只认数据目录根部的 `全链路投放看板.html`。

## 正式更新

- 覆盖正式成品前必须创建时间戳备份并确认备份存在。
- 仅修改模板、CSS 或 JavaScript 时，优先复用正式成品中的现有 payload，避免无必要重跑数据链路。
- 更新后必须核对 payload 未变化，以及星河加载状态、总 GMV、整体 ROI 和本轮新增交互。
- 运行 Python/JavaScript 静态检查和 `scripts/cdp_check.py`；失败时不得交付。
- 成本卡视觉修改必须同时验证桌面与手机：主数字、渠道拆分和均值不得跨出卡片边界；辅助信息固定放在独立底行。
