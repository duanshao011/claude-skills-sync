# 投放看板

把小红书四张投放数据表打通成一个能做判断的交互看板。

## 核心契约（最重要，务必遵守）

**博哥传几张表，就显示几张表的数据；没传的表，前端明确标注"需上传XX表"，不假装有数据；下次传了就更新。**

- 四张表**全部可选**，任意组合都能生成看板。
- 每次触发时，博哥会发来这次要用的表的路径。**只加载他发的表**，没发的一律不加载（脚本默认路径为空）。
- 缺表的字段列在全链路表里显示斜纹"需上传XX表"；数据源状态条显示该表"未上传"。
- 身份列（笔记ID、达人昵称）从任意表都能取，永不标缺失。

## 四张表与字段来源

| 表 | 来源 | 提供的核心字段 |
|---|---|---|
| 蒲公英 | 蒲公英后台导出 xlsx（多级表头，header=2） | 阅读UV、点击率、平均浏览时长、正文/评论区组件点击量、达人昵称、笔记发布日期 |
| 淘宝星河 | 星河导出 xlsx/csv | 进店UV、加购UV、成交UV、商家GMV（按笔记ID聚合，锁"全部流量+归因30天"） |
| 薯条 | 薯条订单明细 xlsx | 实际支付金额（元）→ 聚合成"投放金额"，仅订单状态=推广完成（唯一投放金额来源） |
| 灵犀 | 灵犀种草贡献榜单 xlsx | TI人群数、I+TI人群数、进店用户数、TI人群进店兑换比 |

## 指标口径（2026-07-06 更新）

- **投放金额 = 薯条实际支付金额，仅订单状态=推广完成**（不含达人合作费/退款/优惠抵扣；无薯条则为空）
  - 老薯条表无"实际支付金额"列 → 自动回退到"实际消耗"
  - 老表无"订单状态"列 → 不筛状态
- **ROI = 商家GMV / 投放金额**
- **进店UV价值 = 商家GMV / 进店UV**（星河组 label：进店UV价值，字段 key：uv_value）
- **阅读UV成本（星河组）= 投放金额 / 星河『阅读/播放UV』**（字段 key：uv_cost）
- **阅读UV成本（薯条组）= 投放金额 / 蒲公英『阅读UV』**（字段 key：read_uv_cost）
  - ⚠️ 两个"阅读UV成本"同名不同源：星河组用 read_uv_funnel 分母（归因30天口径），薯条组用 read_uv_content 分母（蒲公英全量口径），靠分组头颜色区分
- **进店UV成本 = 投放金额 / 进店UV**（visit_uv_cost）
- **加购成本 = 投放金额 / 加购UV**；**成交成本 = 投放金额 / 成交UV**
- **组件点击总量 = 正文 + 评论区 + 底栏 三处组件点击量之和**；**组件点击成本 = 投放金额 / 组件点击总量**
- **进店率分母 = 星河『阅读/播放UV』**（星河内部漏斗视角，不是蒲公英阅读UV）
- 判断用**本期相对水位线**（每指标 P25/P75 分档，自适应，不预设死阈值），单元格按档着色。

### 数字格式规范（前端展示）

- **金额（元）** → 严格 2 位小数（fmt.money 用 minimumFractionDigits=maximumFractionDigits=2）
- **率（%）** → 严格 2 位小数（fmt.ratio 用 toFixed(2)）
- **UV / 篇 / 条 / 天** → 整数（fmt.int）
- **ROI / 兑换比 / 平均浏览时长** → 2 位小数（fmt.num）
- **坐标轴刻度**：金额 >=1000 用 k 简写，<1000 用 2 位小数；不做金额严格 2 位以免挤爆

### 水位线着色规则（表格数字颜色 + 表下方图例说明）

- 🟢 绿=本期优秀(排前25%/P75以上) · 🟠 橙=偏弱(后25%/P25以下) · ⚫ 黑=中间50%达标 · 灰"—"=无数据。
- **颜色按指标「越高越好 / 越低越好」自动判向，绿永远=好、橙永远=差**（成本类/兑换比越低越绿）。
- 相对本期这批笔记比较，不是绝对阈值；表格下方有一行小字图例常驻说明。

## 看板结构（生成的 HTML）— 2026-07-06 更新

1. **顶部 KPI**（4 卡）：
   - 总投入(薯条实付) — 右上角小标签显示**薯条投放周期**(启动时间 min~max)
   - 总GMV — 右上角小标签显示**星河数据周期**(日期 min~max)
   - 整体ROI(=GMV/薯条) / 笔记数
   - 缺对应表时该周期标签不显示。
2. **数据源状态条**：四张表逐个显示 ✓已加载N条 / 未上传（灵犀额外显示命中本期数）
   - 每张已上传的表卡片下方带**📅 红色圆角标签**显示该表数据日期范围（min-max）：
     - 蒲公英 → 笔记发布日期(`pub_date`)
     - 星河 → 星河日期(`date`)，两张合并后的整体范围
     - 薯条 → 薯条启动时间(`launch_time`)
     - 灵犀 → 灵犀创建时间(`pub_time`)
   - 未上传的表不显示日期标签。
3. **🔗 联动复选框**：每行图表标题旁。**默认全勾选**，任意搜索框选中笔记 → 所有勾了 🔗 的图表自动同步。不参与联动的取消勾选即可。联动外源笔记（目标模块无该笔记数据）时，搜索框灰斜体显示笔记ID，图表区标注"无数据"。
4. **图表一 · 单篇趋势分析**：

   - **搜索框为空时默认展示全部笔记逐日消耗汇总 + 累计成本虚线**

## 执行流程

1. **默认扫描目录**（2026-07-16 更新）：`D:\C盘迁移归档\桌面工作文件\小红书营销数据\数据看板文件\`
   - 博哥把最新四张表都放这个目录，脚本按文件名关键字自动识别：
     - **蒲公英**：文件名含"蒲公英" → `--pugongying`
     - **星河**：文件名含"星河"或"小红星" → `--star`（可多张，"旧"排前"新"排后自动定序）
     - **薯条**：文件名含"薯条" → `--chili`
     - **灵犀**：文件名含"灵犀" → `--lingxi`
   - 同类多份时取修改时间最新那份；星河可多张全部保留（旧版1234月+新版456月）。
2. **跑脚本**（不传任何参数，全靠默认扫描）：
   ```
   OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python scripts/build_dashboard.py
   ```
   输出目录也默认为扫描目录，产物文件名固定为 `全链路投放看板.html`（覆盖同名）。
   
   **需要更精细控制时**：
   - `--scan-dir "自定义目录"` 换扫描目录
   - `--pugongying/--star/--chili/--lingxi "路径"` 显式指定单表（覆盖扫描结果）
   - `--no-scan` 禁用自动扫描（严格模式）
   - `--start 20260501 --end 20260531` 按蒲公英发布日期筛当期
   - `--prefix "0706"` 归档：变成 `0706_全链路投放看板.html`
3. **看回执**：脚本打印各表加载状态(✓/✗)、周期、口径(含"实际支付·推广完成")、总投入/GMV/ROI。
4. **Edge 无头自检**（不让博哥当测试员）：
   ```
   msedge --headless=new --disable-gpu --no-sandbox --virtual-time-budget=3000 \
     --screenshot="_check.png" --window-size=1500,1250 "成品.html"
   ```
   横滚自检：注入 `scrollLeft=650` 再截，确认横滚后分组头不飘、冻结列对齐。
5. 给博哥成品路径 + 回执要点，说明哪几张表没传、对应哪些字段未显示。

## 文件结构

- `scripts/build_dashboard.py` 主编排（入口，四表可选）
- `scripts/column_map.py` 四表列名容错映射（列名优先、列号兜底）
- `scripts/loaders.py` 四表独立读取清洗（load_pugongying/star/chili/lingxi）
- `scripts/metrics.py` 合并 + 派生指标 + 水位线 + build_cost_daily
- `scripts/render.py` payload 构建(含字段口径元数据) + 内联出单文件
- `assets/` template.html + dashboard.css(小红书红) + dashboard.js + echarts(本地内联)

## 依赖与常见坑

- Python：pandas、openpyxl、numpy。ECharts 已本地内联，HTML 双击即开、零外链。
- 蒲公英多级表头 → `header=2` 读取；星河同笔记多行 → 锁"全部流量+归因30"再按内容ID聚合。
- **星河支持多张表合并**：`--star 旧版.xlsx 新版.xlsx`，后传优先。同 (note_id, date) keep='last'。适用场景：一张表口径改版拆成新老两份、月份分卷导出等。老版可能没有"流量类型/归因周期"列（默认已经是"全部流量+归因30"），loader 自动跳过锁口径。
- **星河日期归一**：老版"时间"字段是"YYYY-MM-DD"字符串（可能含 \t），新版"日期"字段是纯数字 YYYYMMDD。loader 里 `_parse_star_date` 统一归到 int YYYYMMDD。
- 薯条新口径：有 `real_pay` 列时用实际支付、筛"推广完成"；无则回退旧口径（兼容老表）。
- 导出列号/列名漂移 → `column_map.py` 列名优先、列号兜底。
- 主体笔记 = 星河 ∪ 薯条（有转化或有消耗的）。缺蒲公英时其前端字段行级标"—"；下拉框日期显示"—"（历史投放数据蒲公英未覆盖，非异常）。
- **前端自检必须测横滚**：sticky 冻结的 bug 只有横向滚动才暴露，初始态截图看不出来。
- **ECharts 实例防销毁**：切换笔记时如果 entry 不存在，先 `dispose()` 再写 innerHTML，否则后续 `setOption` 往已销毁实例调用会静默失败 → 图表不显示。
- **联动默认勾选**：复选框默认 checked，开箱即用；不需要联动的模块手动取消。
- **联动外源笔记**：`restoreInputDisplay` 先从本模块候选中找，找不到从全局 DATA.notes 取身份信息，确保目标搜索框同步显示笔记 ID 而非保持旧内容。
- **产物固定路径**：默认输出 `全链路投放看板.html`（覆盖同名），博哥用同一路径反复打开。归档才传 `--prefix`。
- **默认无灵犀不阻塞**：四表全部可选；灵犀不给就整行不加载，字段列前端标"—"。
- **自动扫描默认目录**：`build_dashboard.py` 无参运行时扫描 `D:\C盘迁移归档\桌面工作文件\小红书营销数据\数据看板文件\`，按文件名关键字自动识别四表；同类多份取修改时间最新，星河按"旧/新"关键字排序（旧排前新排后，(note_id,date) keep='last' 让新版覆盖旧版）。以 `~` 开头的临时文件自动跳过。
- **查询面板走本地过滤**：462 篇数据全在浏览器 JS 内存（`DATA.notes` 数组），`Array.filter()` 遍历约 1-5ms，实时匹配无需后端。输入即触发用 150ms debounce 防抖，Enter 键立即触发（跳过 debounce）。
- **CSV 导出精度**：整数直出、小数最多 4 位并去尾零；文本含 `,`/`"`/换行时加双引号包裹；首字符 `﻿` UTF-8 BOM 保证 Excel 双击不乱码。
- **图表三查询面板与顶部联动搜索职责分离**：查询面板只作用于表格本身，不参与联动；顶部搜索框参与联动图表一二。样式上一目了然。
