# 全链路投放看板

把三张投放数据表打通成一个能做判断的分析看板。回答 4 个问题：**哪篇笔记优质 / 值不值得追投 / 内容能复用什么 / 该选哪个达人。**

## 核心设计（为什么这么做）

- **主表 = 蒲公英合作笔记**（档案全集），左连接星河（后端转化）、左连接薯条（付费消耗）。
  必须用蒲公英做主表，才能看到「没投薯条但自然转化好」的种子选手——这是值得追投的最高价值群体，用薯条做主表会漏掉。
- **分析主体 = 当期有动作的笔记 = 星河 ∪ 薯条**（有转化或有消耗的）。
- **判断用本期相对水位线**：每个指标按本期全部笔记算 P25/P75 分档（优质/达标/预警），每期自适应，不预设死阈值。
- **总成本 = 达人合作费(蒲公英总金额) + 薯条消耗**；ROI = 星河GMV / 总成本。

## 输入约定（关键）

需要三个文件，**三表时间窗口必须对齐（同一时间段）**：

| 表 | 来源 | 必需字段 |
|---|---|---|
| 蒲公英 | 蒲公英后台导出 xlsx（多级表头） | 笔记id、总金额、各前端内容指标 |
| 星河 | 淘宝星河导出 csv（utf-8-sig） | 内容ID、进店UV、成交UV、商家GMV |
| 薯条 | 薯条后台导出 xlsx | 笔记ID、实际消耗（元） |

⚠️ **窗口对齐是正确性第一前提**：星河给的是某月转化、薯条给的是另一月消耗，会导致大量笔记匹配不上、止损象限虚高。脚本会自动校验并告警，但出准确看板必须导出**同一个月**的三表。

## 执行流程

1. 跟用户确认三张表的路径，以及它们是否同一时间段（不确定就提醒对齐）。
2. 运行主脚本（默认路径已指向桌面示例，正式用传入实际文件）：
   ```
   python scripts/build_dashboard.py \
     --pugongying "蒲公英.xlsx" --star "星河.csv" --chili "薯条.xlsx" \
     --output-dir "输出目录" --prefix "0630"
   ```
   可选 `--start 20260501 --end 20260531` 按蒲公英发布日期筛当期。
3. 看脚本打印的交付回执（周期/口径/对齐状态/总投入/GMV/ROI/重点追投数/最高ROI/推荐达人）。
4. **Edge 无头自检**（不让用户当测试员）：
   ```
   & "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless --disable-gpu \
     --screenshot="_selfcheck.png" --window-size=1500,3600 "成品.html"
   ```
   Read 截图确认五模块都渲染、非空白，再交付。
5. 给用户成品路径 + 回执要点。窗口未对齐时**主动说明**止损象限可能虚高。

## 看板五大模块

1. **全局概览** KPI：总投入/总GMV/整体ROI/笔记数/四象限分布
2. **四象限判断矩阵**（核心）：X=薯条消耗(未投贴左)，Y=转化综合分(进店率·成交率·ROI百分位)，点色=象限、点大小=GMV。四区=加大投/止损/**重点追投**/观察
3. **笔记全链路明细**：每篇一行，内容质量｜转化漏斗｜效率三组列可切换，单元格按水位线着色，可排序筛选
4. **笔记每日趋势**：选一篇看进店/加购/成交逐日曲线
5. **复用洞察**：高ROI笔记共性（形式/达人层级/标签/流量结构的 lift 超配）+ 高ROI稳定达人名单

## 文件结构

- `scripts/build_dashboard.py` 主编排（入口）
- `scripts/column_map.py` 列名容错映射（导出列号漂移收敛于此）
- `scripts/loaders.py` 三表独立读取清洗
- `scripts/metrics.py` 四层指标 + 水位线 + 四象限
- `scripts/insights.py` 复用洞察
- `scripts/render.py` payload 构建 + 内联出单文件
- `assets/` 深色模板 + ECharts(本地内联，离线可开)

## 依赖

Python：pandas、openpyxl、numpy。ECharts 已本地内联，生成的 HTML 双击即开、零外链。

## 常见坑（已在代码中处理）

- 蒲公英多级表头 → `header=2` 读取
- 星河同笔记多行 → 先锁「全部流量 + 归因30天」再按内容ID聚合，否则重复累加
- 薯条混未投行 → 过滤「实际消耗>0」
- 导出列号/列名漂移 → `column_map.py` 列名优先、列号兜底
- 比率字段格式不一(35.2% / 0.352) → 统一解析为 0~1
