# 投放看板

把小红书四张投放数据表打通成一个能做判断的交互看板。

## 核心契约（最重要，务必遵守）

**博哥传几张表，就显示几张表的数据；没传的表，前端明确标注"需上传XX表"，不假装有数据；下次传了就更新。**

- 四张表**全部可选**，任意组合都能生成看板；主表主体为四张表 `note_id` 的并集。
- 默认始终扫描固定目录（`D:\C盘迁移归档\桌面工作文件\小红书营销数据\数据看板文件\`）自动识别四表，无需指定路径。只有用户在”打开看板”指令中明确说”用这个文件”时，才用显式路径覆盖对应表；对话中其他操作（如合并文件、整理数据）涉及的路径不视为看板输入。
- 缺表的字段列在全链路表里显示斜纹"需上传XX表"；数据源状态条显示该表"未上传"。
- 身份列（笔记ID、达人昵称）从任意表都能取，永不标缺失。

## 四张表与字段来源

| 表 | 来源 | 提供的核心字段 |
|---|---|---|
| 蒲公英 | 蒲公英后台导出 xlsx（多级表头，header=2） | 阅读UV、点击率、平均浏览时长、正文/评论区组件点击量、达人昵称、笔记发布日期 |
| 淘宝星河 | 星河导出 xlsx/csv | 进店UV、加购UV、成交UV、商家GMV（按笔记ID聚合，锁"全部流量+归因30天"） |
| 薯条 | 薯条订单明细 xlsx | 实际支付金额（元）→ 聚合成"投放金额"，仅订单状态=推广完成（唯一投放金额来源） |
| 灵犀 | 灵犀种草贡献榜单 xlsx | TI人群数、I+TI人群数、进店用户数、TI人群进店兑换比 |

## 指标口径（2026-07-24 更新）

- **投放金额 = 薯条实际支付金额，仅订单状态=推广完成**（不含达人合作费/退款/优惠抵扣；无薯条则为空）
  - **“实际支付金额”是唯一金额字段**；不读取、不回退到“实际消耗”，缺少该列时薯条表加载失败并明确提示
  - 老表无"订单状态"列 → 不筛状态
- **ROI = 商家GMV / 投放金额**
- **进店UV价值 = 商家GMV / 进店UV**（星河组 label：进店UV价值，字段 key：uv_value）
- **阅读UV成本（星河组）= 投放金额 / 星河『阅读/播放UV』**（字段 key：uv_cost）
- **所有业务漏斗UV以星河为唯一口径**：阅读=`read_uv_funnel`、进店=`visit_uv`、加购=`cart_uv`、成交=`deal_uv`。蒲公英 `read_uv_content` 只作为前端内容原始参考字段保留，不参与进店率、成本、ROI或默认业务展示。
- 历史字段 `read_uv_cost`（薯条金额 / 蒲公英阅读UV）仅保留底层兼容，不进入默认列、业务判断或图表；正式阅读成本统一使用星河 `uv_cost`。
- **进店UV成本 = 投放金额 / 进店UV**（visit_uv_cost）
- **加购成本 = 投放金额 / 加购UV**；**成交成本 = 投放金额 / 成交UV**
- **组件点击总量 = 正文 + 评论区 + 底栏 三处组件点击量之和**；**组件点击成本 = 投放金额 / 组件点击总量**
- **进店率分母 = 星河『阅读/播放UV』**（星河内部漏斗视角，不是蒲公英阅读UV）
- 判断用**本期相对水位线**（每指标 P25/P75 分档，自适应，不预设死阈值），单元格按档着色。

### 全链路爆款笔记筛选

用户要求筛选“综合爆款”时，不按阅读量、GMV或ROI单指标排序：

1. 仅纳入四表齐全，且进店UV、加购UV、成交UV均大于0的笔记，避免缺数据或漏斗断层。
2. 各指标先转换为候选笔记中的百分位排名；成本类和TI人群进店兑换比反向计分（越低越好），避免量纲和极端值主导结果。
3. 默认分组权重：前端内容15%、进店20%、加购20%、成交25%、商业效率10%、人群资产10%。
   - 前端内容：阅读UV、内容点击率、平均浏览时长、组件点击总量。
   - 进店：进店UV、进店率。
   - 加购：加购UV、加购率。
   - 成交：成交UV、成交率、GMV、进店UV价值。
   - 商业效率：ROI、成交成本。
   - 人群资产：TI人群数、灵犀进店用户数、TI人群进店兑换比。
4. 必须增加权重敏感性检查：至少用“均衡、转化优先、种草优先”三套权重重算。名单稳定的笔记才可称为综合爆款；只在单套权重入选的标为候选。
5. 输出TOP5时同时给出入选理由和短板，区分“规模型爆款”和“效率型爆款”，并提示星河多内容归因导致GMV适合相对比较、不宜直接相加。

### 数字格式规范（前端展示）

- **金额（元）** → 严格 2 位小数（fmt.money 用 minimumFractionDigits=maximumFractionDigits=2）
- **率（%）** → 严格 2 位小数（fmt.ratio 用 toFixed(2)）
- **UV / 篇 / 条 / 天** → 整数（fmt.int）
- **ROI / 兑换比 / 平均浏览时长** → 2 位小数（fmt.num）
- **坐标轴刻度**：金额 >=1000 用 k 简写，<1000 用 2 位小数；不做金额严格 2 位以免挤爆

### 水位线着色规则（表格数字颜色 + 表下方图例说明）

- 🟢 绿=本期优秀(排前25%/P75以上) · 🟠 橙=偏弱(后25%/P25以下) · ⚫ 黑=中间50%达标 · 灰"—"=无数据。
- **颜色按指标「越高越好 / 越低越好」自动判向，绿永远=好、橙永远=差**（成本类/兑换比越低越绿）。
- 相对本期这批笔记比较，不是绝对阈值；表格下方有一行小字图例常驻说明。

## 视觉规范（2026-07-24 确认）

采用**小红书商业化专业版**，目标是简洁、清爽、高级，同时适配高密度业务数据：

- 视觉底色：雾灰 `#F7F7F8` + 白色内容画布；品牌主色固定 `#FF2442`，浅粉 `#FFF0F2` 只用于选中、重点和状态提示，禁止满屏红。
- 层级方式：减少厚重边框和彩色装饰，用 18px 大模块圆角、14px 指标卡圆角、轻阴影和留白建立层级。
- 页头与目录：品牌红竖线强化标题；目录使用白色半透明悬浮卡和浅粉激活态。
- 控件：输入框、按钮、胶囊切换统一圆角和焦点环；保留键盘可见焦点，兼容 `prefers-reduced-motion`。
- 图表指标卡：浅灰底、左对齐、重点数字，不用大面积彩色卡；图表颜色和全部交互逻辑保持原样。
- 图表下方指标胶囊的状态优先级固定为：`.active:hover` 继续使用该指标 `--mc` 实色背景与白字；仅未选中胶囊 hover 时允许切换白底，避免“选中 + 悬浮”后白底白字。
- 图表四顶部联动下拉固定为“发布日期｜笔记ID｜达人昵称”网格列，列表禁止横向滚动；长笔记ID和达人昵称使用省略号，完整内容仍保留在数据中。
- 全链路表：降低网格噪音，但必须保留蒲公英/星河/薯条/灵犀分组辨识色、sticky 层级和不透明表头背景。

## 执行流程

### 日常修改与原 HTML 安全更新

前端样式和脚本会被内联进最终单 HTML，因此只改 `assets/` 源文件不会自动改变博哥当前打开的旧页面。日常修复遵循：

1. 先修改源文件并执行 Python/JavaScript 语法、关键字符串和 `git diff --check` 检查。
2. 原看板固定为 `D:\C盘迁移归档\桌面工作文件\小红书营销数据\数据看板文件\全链路投放看板.html`；日常修改直接更新该文件，不生成“验证版”网页。
3. 覆盖前先创建时间戳备份 `全链路投放看板_覆盖前备份_YYYYMMDD-HHMMSS.html`，确认备份存在后再更新原文件。
4. 若本轮只改 CSS/JavaScript，且扫描目录内数据文件结构有变化或自动扫描不可靠，优先把已验证的源代码片段注入备份后的原 HTML，避免无必要重跑数据链路。
5. 若必须重新生成，先核对自动识别到的每一份输入表，再运行脚本；生成后必须验证星河加载状态、总GMV、整体ROI及关键交互契约。任一核心数据异常，立即停止交付并从备份恢复。
6. 图表三改动需额外硬校验：存在3日滚动计算、累计基线、多指标分面、共享 `axisPointer`；多成本 tooltip 必须由 `buildCostTooltip` 生成，单指标保留固定三行，多指标合并为“指标为行、口径为列”的单张交叉表，表头顺序固定为“当日成本 / 3日滚动 / 累计基线”；汇总阅读索引为5、单篇阅读索引为6；胶囊/KPI仍读取周期累计 summary；旧的蒲公英阅读UV成本逻辑不得出现在图表三。
7. 更新完成后让博哥刷新或重新打开同一个原 HTML；仅在博哥明确要求归档时才使用 `--prefix`。

### 数据生成流程

1. **默认扫描目录**（2026-07-16 更新）：`D:\C盘迁移归档\桌面工作文件\小红书营销数据\数据看板文件\`
   - 博哥把最新四张表都放这个目录，脚本按文件名关键字自动识别：
     - **蒲公英**：文件名含"蒲公英" → `--pugongying`
     - **星河**：文件名含"星河"或"小红星" → `--star`（可多张，"旧"排前"新"排后自动定序）
     - **薯条**：文件名含"薯条" → `--chili`
     - **灵犀**：文件名含"灵犀" → `--lingxi`

2. **跑脚本**（不传任何参数，全靠默认扫描）：
   ```
   OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python scripts/build_dashboard.py
   ```
   输出目录也默认为扫描目录，产物文件名固定为 `全链路投放看板.html`（覆盖同名）。
   
   **需要更精细控制时**：
   - `--scan-dir "自定义目录"` 换扫描目录
   - `--pugongying/--star/--chili/--lingxi "路径"` 显式指定单表（覆盖扫描结果）
   - `--no-scan` 禁用自动扫描（严格模式）
   - `--start 20260501 --end 20260531` 按蒲公英发布日期筛当期
   - `--prefix "0706"` 归档：变成 `0706_全链路投放看板.html`
3. **看回执**：脚本打印各表加载状态(✓/✗)、周期、口径(含"实际支付·推广完成")、总投入/GMV/ROI。
4. **Edge 无头自检**（不让博哥当测试员）：
   ```
   msedge --headless=new --disable-gpu --no-sandbox --virtual-time-budget=3000 \
     --screenshot="_check.png" --window-size=1500,1250 "成品.html"
   ```
   横滚自检：注入 `scrollLeft=650` 再截，确认横滚后分组头不飘、冻结列对齐。
5. 给博哥成品路径 + 回执要点，说明哪几张表没传、对应哪些字段未显示。

## 文件结构

## 依赖与常见坑

- Python：pandas、openpyxl、numpy。ECharts 已本地内联，HTML 双击即开、零外链。
- 蒲公英常规后台导出为多级表头，优先 `header=2` 读取；历史标准化文件可能首行就是 `note_id/creator/pub_date` 等标准列，loader 必须检测关键字段，未命中时自动回退 `header=0`。禁止对标准化文件强行套 `header=2`，否则会把第3条数据当表头并导致笔记ID、达人昵称、发布日期整体错位。
- **星河支持多张标准明细表合并**：`--star 旧版.xlsx 新版.xlsx`，后传优先。同 (note_id, date) keep='last'。适用场景：一张表口径改版拆成新老两份、月份分卷导出等。老版可能没有"流量类型/归因周期"列（默认已经是"全部流量+归因30"），loader 自动跳过锁口径。
- **禁止把星河派生宽表当原始明细**：扫描目录可能出现“星河分日趋势”“星河汇总”等二次加工文件，它们虽含“星河”关键字，但结构不是标准星河明细。自动生成前必须核对候选文件名和核心列；发现此类宽表时排除，或显式传入正确 `--star` 路径。否则可能导致星河整体加载失败、GMV/ROI变空。
- **星河日期归一**：老版"时间"字段是"YYYY-MM-DD"字符串（可能含 \t），新版"日期"字段是纯数字 YYYYMMDD。loader 里 `_parse_star_date` 统一归到 int YYYYMMDD。
- 薯条唯一金额口径：必须有 `real_pay`（实际支付金额）列，并筛“推广完成”；不兼容“实际消耗”回退。
- 导出列号/列名漂移 → `column_map.py` 列名优先、列号兜底。
- 主体笔记 = 蒲公英 ∪ 星河 ∪ 薯条 ∪ 灵犀 的 `note_id` 并集；任意单表或组合都能生成。缺蒲公英时其前端字段行级标“—”，下拉框日期显示“—”。
- **前端自检必须测横滚**：sticky 冻结的 bug 只有横向滚动才暴露，初始态截图看不出来。分组表头必须保持不透明业务底色，禁止 hover 时使用 `background: inherit`；表头层级应高于 body 冻结列。修复源 CSS 后必须同步更新/重新打开内联 CSS 的原 HTML。
- **ECharts 实例防销毁**：切换笔记时如果 entry 不存在，先 `dispose()` 再写 innerHTML，否则后续 `setOption` 往已销毁实例调用会静默失败 → 图表不显示。
- **联动默认勾选**：复选框默认 checked，开箱即用；不需要联动的模块手动取消。
- **联动外源笔记**：`restoreInputDisplay` 先从本模块候选中找，找不到从全局 DATA.notes 取身份信息，确保目标搜索框同步显示笔记 ID 而非保持旧内容。
- **灵犀“作业昵称”不能无条件当达人昵称**：灵犀可能把品牌账号或项目账号统一写成“光粒”，这不是笔记真实达人名。身份来源优先级应为蒲公英达人昵称、星河达人昵称、薯条被推广者、灵犀作业昵称；灵犀中的“光粒”等品牌占位值只能作为来源字段保留，不能回填全链路表的达人昵称。没有其他真实昵称来源时显示“—”，禁止展示伪达人名。
- **产物固定路径**：所有日常修改、修复和验证都直接覆盖原 `全链路投放看板.html`，让博哥在原页面刷新查看；禁止为验证单独生成新网页。只有博哥明确要求归档时才传 `--prefix`。
- **默认无灵犀不阻塞**：四表全部可选；灵犀不给就整行不加载，字段列前端标"—"。
- **自动扫描默认目录**：`build_dashboard.py` 无参运行时扫描 `D:\C盘迁移归档\桌面工作文件\小红书营销数据\数据看板文件\`，按文件名关键字自动识别四表；蒲公英/星河/薯条多份全部加载，星河按 `(note_id,date)` 去重，薯条按 `订单ID` 去重，灵犀取最新；以半角波浪符开头的临时文件自动跳过。
- **图表四只保留顶部联动搜索**：二级查询面板及其查询、重置、CSV 导出入口已从模板移除；表格排序、分页、自定义列和顶部搜索继续保留。
- **效率指标必须同样本**：总投入和总GMV可分别展示各自来源全量，但任何汇总成本或整体ROI的分子、分母必须限定为薯条与星河均命中的同一批笔记，并显示交集覆盖篇数；禁止用全量薯条花费除全量星河UV，或用全量星河GMV除全量薯条花费。
- **图表二星河漏斗口径**：单篇“总阅读UV”和进店率必须使用星河 `read_uv_funnel`；不得优先取蒲公英 `read_uv_content`。蒲公英阅读UV只用于前端内容指标。
- **水位线排除缺来源补零**：每项P25/P75只在该指标所属来源真实存在的记录内计算；缺来源保持空值并排除排名，来源内真实0值可以参与。修复后偏弱/中间/优秀应接近25%/50%/25%，不得因四表并集补0导致偏弱档消失。
- **累计指标保持周期整体口径**：薯条实付日期与星河归因行为日期存在延迟，逐日阅读/进店成本属于自然日近似值；趋势和累计效率仍须遵守同样本原则，不因日期近似放宽分子分母集合。
- **3日滚动必须是自然日窗口**：正式展示“3日滚动”前先补齐自然日，缺失日花费与UV设为0，再取当前日及前2个自然日；若仍按最近3个数据点计算，文案必须写“近3个数据点”，禁止称为“3日滚动”。
- **多指标禁止同轴硬叠**：阅读、进店、加购、成交成本数量级不同；选择2项及以上时必须分面并使用独立Y轴，不使用一个Y轴或多条双Y轴强行叠加。
- **成品交付硬校验**：更新原 HTML 后至少验证 `meta.sources.star.loaded=true`、`summary.total_gmv>0`、`summary.overall_roi` 非空，以及本轮新增/删除的DOM或tooltip文案顺序。图表三还需验证 `buildCostTrendData`、多选分面、轴联动和新说明文案。核心数据或交互不满足即恢复备份，不交付半成品。
