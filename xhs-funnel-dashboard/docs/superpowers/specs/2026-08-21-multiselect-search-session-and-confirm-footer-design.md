# 全链路表格多关键词选择与固定确认栏设计

## 目标

修正全链路表格的笔记多选交互，使用户能连续搜索多个关键词并累计勾选笔记，同时让确认操作始终稳定地显示在下拉框底部。

## 已确认方案

采用“单次打开、单次临时选择会话”的方案：

- 打开下拉框时，只初始化一次临时选择 `draftIds`。
- 同一次打开期间，搜索框聚焦、输入关键词和切换关键词都只过滤候选项，不重置 `draftIds`。
- 已勾选但被新关键词过滤掉的笔记仍保留在 `draftIds` 中。
- 点击确认后，将整组 `draftIds` 提交到表格并结束会话。
- 点击外部或按 `Esc` 时放弃本轮临时改动，恢复已确认选择并结束会话。
- 点击清除时同时清空已确认选择和当前临时选择，并结束会话。

## 组件结构

下拉面板拆成两个互不覆盖的区域：

1. 候选滚动区：只承载搜索结果和复选项，独立纵向滚动。
2. 固定确认区：位于面板最底部，不参与滚动，使用不透明背景并与面板四边无缝衔接。

确认区只保留一个居中按钮：

- `draftIds` 为空时显示“确认”，按钮灰色且禁用。
- `draftIds` 非空时显示“确认 N 篇”，按钮使用可点击的品牌红色。
- 不再单独显示“已选 N 篇”文字。

## 状态与数据流

新增明确的选择会话状态 `draftActive`：

- 新会话：从 `TABLE.selectedIds` 复制到 `draftIds`，并将 `draftActive` 设为真。
- 会话中：搜索和重新渲染只读取 `draftIds`，不得再次从 `TABLE.selectedIds` 覆盖。
- 提交或取消：按对应规则处理后将 `draftActive` 设为假。

表格数据和平均值只响应已确认的 `TABLE.selectedIds`。临时选择期间不提前刷新表格，也不改变平均值。

## 边界行为

- 搜索无结果时，候选区显示空状态，固定确认按钮仍可反映此前跨关键词累计的选择数量。
- 用户搜索关键词 A 勾选一篇，再搜索关键词 B 勾选一篇，按钮应显示“确认 2 篇”。
- 确认后表格显示两篇，平均值按已确认的两篇计算。
- 已确认选择重新打开时，按钮按当前已确认篇数显示；取消后不改变表格。

## 验收标准

- 跨两个不同关键词累计勾选后，临时选择数量保持正确。
- 未确认时，表格行数和平均值不变化。
- 0 篇时按钮显示“确认”、灰色、禁用。
- 有选择时按钮显示“确认 N 篇”并可点击。
- 确认栏固定在下拉面板底部中央，背景不透明。
- 候选项不能滚动到确认栏下方，确认栏与候选区、面板底部均无可见缝隙。
- 原有确认、外部取消、`Esc` 取消、清除和跨图表联动语义保持不变。

## 修改范围

- `assets/dashboard.js`：选择会话、渲染结构和按钮状态。
- `assets/dashboard.css`：候选滚动区与固定确认区布局。
- `scripts/cdp_check.py`：增加跨关键词累计选择和底部布局断言。
- `SKILL.md`：沉淀多选会话和固定确认按钮规则。
- 使用 Skill 构建脚本安全覆盖原 `全链路投放看板.html`，覆盖前创建时间戳备份。

不改变数据口径、平均值计算规则、其他图表联动规则或数据源加载逻辑。
