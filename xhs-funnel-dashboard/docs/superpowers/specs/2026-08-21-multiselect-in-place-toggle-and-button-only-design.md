# 全链路笔记多选原地勾选与单按钮设计

## 目标

修复勾选笔记后下拉列表滚动位置跳动的问题，并移除确认按钮背后的整条白色遮挡层。

## 已选方案

采用原地更新方案。用户点击笔记时不再重新执行 `renderList()`，只更新当前候选项的选中样式、`aria-selected`、复选框视觉状态和确认按钮文案。由于候选 DOM 和滚动容器均不重建，列表的 `scrollTop` 及页面位置保持不变。

搜索关键词发生变化时仍允许重新渲染候选列表，因为这是用户主动切换结果集；跨关键词累计的 `draftIds` 保持不变。

## 确认按钮

- 删除当前占满下拉框宽度的 `.table-multi-confirm` 白色栏。
- 面板内只保留一个底部居中的 `.table-confirm-btn`。
- 按钮固定在面板底部，外层仅负责定位，不设置白色背景、顶部边框或阴影。
- 候选滚动区增加与按钮高度匹配的底部留白，确保最后一条候选可以完整滚动到按钮上方，不被按钮遮挡。
- 0 篇时显示灰色禁用“确认”；有选择时显示红色可用“确认 N 篇”。

## 交互规则

- 鼠标点击任意可见候选项后，列表滚动位置变化不得超过 1px。
- 键盘 `Enter` 勾选当前高亮项时同样只原地更新，不触发列表重建。
- 键盘上下方向键仍可改变高亮项并在必要时仅滚动候选区，不滚动页面。
- 确认、点击外部取消、`Esc` 取消、清除和跨关键词累计选择规则保持不变。
- 临时勾选仍不刷新表格和平均值，确认后才提交。

## 实现边界

- `dashboard.js`：拆分“更新单项”和“更新确认按钮”逻辑；`toggle()` 不再调用 `renderList()`。
- `dashboard.css`：确认容器改为透明定位层，仅显示按钮；候选区预留按钮空间。
- `cdp_check.py`：增加顶部、中部、底部勾选前后滚动位置和页面位置断言，并检查确认容器无背景、无边框、无阴影。
- `SKILL.md`：沉淀原地勾选和单按钮规则。
- 备份后重建固定路径的原 `全链路投放看板.html`。

不改变数据口径、平均值规则、表格筛选结果或其他图表联动。

## 验收标准

- 点击列表中部或底部笔记后，候选区 `scrollTop` 保持不变，页面 `scrollY` 保持不变。
- 下拉框底部只看到一个确认按钮，不存在整条白色遮挡层。
- 最后一条候选可完整显示在确认按钮上方。
- 跨两个关键词累计选择仍显示“确认 2 篇”，确认后表格显示两篇。
- 原有自动验收全部通过。
